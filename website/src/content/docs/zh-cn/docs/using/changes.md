---
title: 改动与文件预览
description: 在 Condr 中快速查看 Agent 修改的文件、对比代码差异（Diff）以及预览项目文件。
---

当 Agent 修改或重构代码时，你需要快速确认改动了哪些文件以及改动是否正确。Condr 内置了文件改动与预览视图，也能直接对文件做简单修改，无需打开外部 IDE 即可完成审查。

## 打开改动面板 (Changes)

- **快捷键**：按下 `Cmd + Option + B` (macOS) 或 `Ctrl + Alt + B` (Windows/Linux)。
- **界面入口**：点击窗口最右侧按钮列中的 **变更**（Changes）；再点一次即可收起右侧栏。

改动视图会根据 Git 状态将修改的文件分为三组：
- **冲突**（Conflicts）：存在合并冲突的文件。
- **已跟踪**（Tracked）：已追踪并被修改的文件。
- **未跟踪**（Untracked）：Agent 新建但尚未纳入 Git 追踪的文件。

每一个文件后都会标出新增和删除的行数，列表上方比较对象按钮那一行的右端汇总累计变动行数。

列表会自动跟随磁盘上的变化。如果某次没跟上，比如项目在网络盘上，点击侧栏右上角的 **刷新**（Refresh），让 Device 重新扫描这个 Workspace；文件（Files）和当前打开的 diff 也会一起刷新。

## 对比 HEAD 或 base 分支

改动列表上方的按钮写着当前的比较对象，例如 `对比 main`（Against main），点开菜单可以改选：

- **HEAD**：只列出尚未提交的改动。Agent 提交之后，这些文件就会从列表中消失。
- **base 分支**：菜单里显示分支名，例如 `main`。列表包含这条分支从分叉点以来的全部改动，已提交和未提交的都在内，base 分支后来新增的提交不会列入。

Condr 新建 Worktree 时，会把父 Workspace 当时所在的分支记为 base 分支。其他 Workspace 依次使用远端的默认分支（例如 `origin/main`）、本地的 `main` 和 `master`。当前分支本身就是 base 分支或它的上游时，只能对比 HEAD。

每个 Workspace 分别记住自己的选择。

## 查看代码差异 (Diff)

1. 在 **变更**（Changes）列表中点击任意文件，中间区域会自动打开 **Diff Pane**；第一次打开时它独占一个 Tab，把这个 Tab 拖到终端上就能并排审查（见 [Workspace、Tab 与 Pane](/zh-cn/docs/using/workspaces/)）。
2. 页面会以高亮形式展示该文件相对于所选比较对象的具体改动，标题栏会标出比较对象，例如 `对比 main`（Against main）。
3. **并排**（Split，两栏图标）把新旧文件左右并排显示，**统一**（Unified，两行图标）把它们合在一栏里。标题栏里的这个选择对所有 Diff Pane 生效，并会被记住。
4. 没有改动的大段内容会折叠起来，点击折叠行可以向上、向下展开更多行，或全部展开。
5. 点击标题栏的 **显示文件**（Show File），会在 Preview Pane 中打开该文件，并定位到你在 diff 中最后点击的那一行。

> **提示**：极大的二进制文件或单文件超过 1 MiB 时，出于性能保护会自动隐藏明细对比。

## 浏览提交历史 (Git History)

点击窗口最右侧按钮列中的 **Git 历史**（Git History），可以看到 Workspace 当前分支的提交记录，最新的在最上面，每个提交总在它的父提交之上：

- **最上面一行**显示分支名；分支有上游时，还显示截至上次 fetch 领先（`↑2`）和落后（`↓1`）的提交数。
- **每一行**显示提交标题、短 ID、作者和提交时间。Agent 提交后，新提交会自动出现在最上面。
- **点击提交**会在提交列表下方的区域列出它改动的文件，以及每个文件新增和删除的行数；拖动两块之间的分隔线可以调整大小，再次点击该提交即可收起。点击文件，会在 Diff Pane 中打开该提交对这个文件的改动；标题栏下方显示提交标题，点旁边的箭头可以展开完整的提交说明。
- **复制提交 ID**：在 Diff Pane 的标题栏或提交的右键菜单中都可以复制。
- 列表末尾的 **显示更多**（Show more）会再加载 100 条提交。

Git 历史（Git History）只读取仓库，不会检出、回滚或创建提交。在 **变更**（Changes）中点击文件，Diff Pane 会回到工作区的改动。

## 一次看全部分支 (Git Graph)

点击 Git 历史标题栏里的提交图按钮，或在命令面板中选择 **打开 Git Graph**，即可打开 **Git Graph**：Workspace 所有分支和标签上的提交，布局和 IntelliJ IDEA 的 Git 日志一样。

- **左侧是分支**：`HEAD`，然后是本地、远程（每个 remote 一组）和标签，`feat/search` 这样的名字按文件夹分组。在上方输入框里输入可以查找。双击一个分支只看它的提交；提交列表上方的过滤条会显示分支名，点它的清除按钮回到全部分支。
- **中间是提交**：每个标题旁画出分支如何分叉、合并的提交图，并标出指向该提交的分支和标签，后面是作者、日期和短 ID。合并提交显示为灰色，你自己的提交加粗。往下滚动会自动加载更多提交。在 **文本或哈希** 中输入后按回车，只保留提交说明含有该文本、或 ID 以 7 位以上哈希开头的提交。
- **右侧是选中的提交**：上面是它改动的文件，下面是提交说明、作者和时间、其他人提交时的提交者、它的分支和标签，以及它所在的全部分支。双击文件，在 Diff Pane 中查看该提交对它的改动。
- **按键**：上下键在提交间移动，右键跳到父提交，左键跳到子提交；`Cmd + L`（`Ctrl + L`）跳到文本过滤框，`Cmd + D`（`Ctrl + D`）打开选中文件的 diff。提交的右键菜单可以复制 ID，或跳到父提交、子提交。

`HEAD` 或它的上游移动时 Git Graph 会自动重新加载；别处 fetch 或提交的分支，点 **刷新**（Refresh）即可看到。和 Git 历史一样，它只读取仓库。

## 一个 Workspace 里的多个仓库

Workspace 的文件夹里直接放着几个仓库（例如 `api/` 和 `web/`）时，Condr 会分别显示每个仓库；文件夹本身也是仓库时，它自己的仓库照常显示在旁边：

- **变更**（Changes）在冲突、已跟踪和未跟踪各组里，把每个有改动的仓库列为单独的一行，显示它在该组的文件数和所在分支。没有改动的仓库不列出。
- **Git 历史**（Git History）和 **Git Graph** 一次显示一个仓库；Git 历史顶部一行、Git Graph 过滤条最前面的菜单列出各仓库的分支，用来切换仓库。
- **文件**（Files）按各仓库自己的忽略规则把文件变灰。
- 左侧栏里 Workspace 的那一行显示文件夹自己仓库的分支；文件夹本身不是仓库时，显示它有几个仓库。在文件夹里 clone 出新仓库后，它会自动出现。

只算直接放在文件夹里的仓库（submodule 也算），不算更深层的仓库。文件夹自己的仓库照常列出改动，但这些仓库里的内容交给它们各自显示。只有文件夹自己的仓库能对比基准分支、新建 Worktree；文件夹本身不是仓库时，Workspace 只能对比 HEAD。文件夹是某个仓库的子文件夹时，变更（Changes）只列出文件夹里的改动。

## 浏览项目文件与预览 (Files & Preview)

- **切换至文件树**：点击窗口最右侧按钮列中的 **文件**（Files），即可像文件管理器一样展开和浏览项目文件夹。
- **改动标记**：有修改的文件夹旁会带有一个圆点标记，被 `.gitignore` 忽略的文件会自动变灰。
- **点击预览**：点击任意文本文件即可在 **Preview Pane** 中打开。文件在磁盘上发生变化时，语法高亮与滚动位置会自动刷新。
- **Markdown 与图片渲染**：Markdown 与 SVG 文件默认以渲染后的效果打开，可在 Pane 顶部的 **预览**（Preview）与 **源码**（Source）间随时切换。常见格式图片（PNG、JPEG、GIF、WebP、BMP、ICO、TIFF，约 2 MiB 以内）会自动缩放适应窗口，动图可直接播放。Markdown 中的图片仅支持加载项目本地文件，网络图片则显示其替代文字。

## 编辑文件 (Preview)

Preview Pane 的 **源码**（Source）视图就是一个编辑器，在本地和远程 Device 上均可使用：

- **编辑与保存**：直接修改文件内容，然后按 `Cmd + S` (macOS) 或 `Ctrl + S` (Windows/Linux) 保存。它所在的 Tab 上的圆点表示有未保存的改动。Condr 不会自动保存，改动只在你保存时写入文件，不会趁 Agent 写文件时自动覆盖。
- **改动行标记**：行号左侧用竖条标出新增（绿色）和修改（黄色）的行，红色标记表示此处删除了行；滚动条上也有同样的标记，长文件里的改动一眼就能找到。对比的基准与 **变更**（Changes）相同（`HEAD` 或基准分支），会随你未保存的输入实时更新，只在 Git 项目中显示。
- **保留换行符**：使用 Windows 换行符（`CRLF`）的文件，新增的行也会沿用 `CRLF`。
- **文件在磁盘上被改动时**：你还有未保存的改动时，如果 Agent 写入了该文件，你的文本会保持不变，顶部会显示 **磁盘上的文件已更改**（Changed on disk）。此时保存会询问是用当前文本 **覆盖**（Overwrite），还是 **放弃并重新加载**（Discard and Reload）。
- **未保存的改动不会被静默丢弃**：在切换到其他文件、关闭 Pane、它所在的 Tab 或退出 Condr 之前，Condr 都会先询问是否保存。若另一台设备切换或关闭了该 Pane，你仍然可以选择保存、复制或放弃当前文本。
- **只读文件**：非有效 UTF-8 文本、二进制文件以及超过 1 MiB 的文件只能查看、无法编辑，顶部会说明原因。

## 快捷右键菜单

在变更（Changes）或文件（Files）列表中的文件上右键，可选择以下常用操作：

- **在 … 中打开**（Open in …）：选择用本地已安装的 VS Code、Zed、Cursor 或 IntelliJ IDEA 打开当前文件或项目。
- **将路径插入终端**（Insert Path into Terminal）：快速将文件的相对路径粘贴到最近使用的终端窗格中，方便传给命令行工具。
- **复制相对路径 / 复制路径**（Copy Relative Path / Copy Path）：一键复制文件相对路径或绝对路径。
- **在 Finder 中显示 / 在文件资源管理器中显示 / 打开所在文件夹**（Reveal in Finder / Reveal in File Explorer / Open Containing Folder）：在系统文件管理器中显示该文件或文件夹（仅限本地 Device）。
- **新建文件… / 新建文件夹…**（New File… / New Folder…）：在文件（Files）视图中创建条目：可在文件夹内新建、在文件旁同级新建，或在文件树下方的空白处新建到项目根目录。新文件会在 Preview Pane 中打开，可直接输入。
- **重命名…**（Rename…）：在所在文件夹内重命名文件或文件夹，若名称已被占用则会拒绝。
- **删除…**（Delete…）：确认后删除文件，或删除文件夹及其全部内容。删除是永久性的，不进入系统回收站。

Condr 不会改动 `.git` 里的任何内容。
