# Agent Status Comes From Hooks Over OSC 777

An Agent's state (`Idle`, `Working`, `Blocked`) is reported by the agent CLI itself, through hooks that Condr installs into that CLI's own configuration. Condr no longer classifies the terminal screen. The herdr-ported detection engine, its TOML manifests, the `agent-detection` overrides, the OSC 9;4 progress evidence and the hysteresis around them are removed rather than kept as a fallback. An agent that Condr recognizes by process but that has not reported anything is `Unknown`, and stays `Unknown`; silence is never turned into `Idle`.

Every installed hook runs the same command, `condr agent-hook <agent> <event>`. It reads the CLI's JSON from stdin, keeps only what Condr needs, and writes one `ESC ] 777 ; notify ; condr://agent ; {json} BEL` sequence to its controlling terminal: `/dev/tty` on Unix; on Windows `CONOUT$` after `AttachConsole` to the Pane's own process, the ancestor whose parent is the Server, because the console the hook inherits need not be the ConPTY (Claude Code spawns its shell with `CREATE_NO_WINDOW`, which gives the hook a private, invisible conhost), with the inherited console and then each ancestor as fallbacks. ConPTY passes the unknown OSC through to the Server unchanged. The Server's PTY reader already scans output for OSC 7/9/1337 before the VT sees it; that scanner now also recognizes the `condr://agent` sentinel, strips the sequence so it never reaches the grid or a client, and hands the event to the Terminal monitor. The hook exits without writing when `CONDR_ENV` is unset, so the same configuration is inert in any other terminal.

In-band transport was chosen over the socket that `CONDR_SOCKET_PATH` already exposes. The event is bound to the PTY it was written to, so no Pane id has to survive the environment of a nested shell or `env -i`; and it is ordered with the output it describes, so a `Stop` never arrives before the final frame. The bytes would also survive an `ssh` to a host that has `condr` and the hooks installed, but the hooks gate on `CONDR_ENV`, which `ssh` does not forward unless the client sends it (`SendEnv`) and the server accepts it (`AcceptEnv`); and `tmux` drops unknown OSC sequences unless passthrough is configured, which Condr does not wrap for. Neither is supported today. The costs are accepted: a hook must locate its controlling terminal, the payload stays well under the scanner's size cap, and any process in the Pane can forge an event, which is the trust an agent running there already has. An agent the agent itself runs (Claude Code calling `claude -p` from a tool) has the same hooks and the same terminal; the hook walks its ancestors and stays silent when a second instance of its agent sits above the first. Consecutive agent processes are one instance, because `codex` is a Node wrapper that spawns the native binary, often behind a version manager's shim; a shell between two agent processes is the agent running a tool, so what follows is another instance. An agent spawning another directly, without a shell, is not told apart.

The state machine is small and the same for every agent. Turn boundaries map to `Idle` and `Working`; a permission request, a question or an elicitation maps to `Blocked`; a tool starting or completing maps to `Working`, which is what ends a `Blocked` once the user answers. A session start caused by compaction is ignored, because it happens mid-turn. Process exit still clears the Agent, as before, because no CLI promises a final hook. The GUI's `Done` remains a presentation of an unseen `Idle`, not a wire state. The CLI's `agent prompt` and `agent wait` consume these states unchanged, and a Pane whose agent has never reported is refused with `agent_not_ready` instead of being guessed at.

Support is per agent and deliberately narrow. The first integrations are Claude Code (`~/.claude/settings.json`), Codex (`~/.codex/hooks.json`, with the `hooks` feature enabled) and OpenCode (a generated plugin under its config directory, chosen because it exercises the third integration shape: an event stream bridged by a file Condr owns). Installation merges into the user's file and marks its own entries with the `condr agent-hook` command so it can report installed, outdated or missing and uninstall without touching anything else. The CLI does this locally (`condr agent hooks install|uninstall|status <agent>`); the GUI's Settings → Server → Agents page asks the connected Server through `AgentCommand::Hooks`, because the hooks live where the agents run, which for a remote Server is another machine. Known gaps are documented per agent rather than papered over: Claude Code fires no hook on a user interrupt, so an interrupted turn shows `Working` until the next event; a permission request that another hook auto-resolves shows `Blocked` until the tool completes; Codex (0.146 and 0.153) fires `SessionStart` with the first turn rather than at startup, so a fresh Codex stays `Unknown` until prompted; for agents that report nothing at startup, `agent start` returns once the process is identified and the first `agent prompt` is accepted in `Unknown`, the one place a state is not taken from a hook. A Codex still showing its directory-trust or hooks-review dialog is `Unknown` too, and a blind first prompt would answer that dialog, which the orchestrating agent avoids by reading the Pane first. Codex runs its hooks through the session shell, PowerShell on Windows, where a quoted path is a string literal, so the installed command carries the `&` call operator there when `condr` is not on PATH; Claude Code runs hooks through Git Bash and gets the plain form. Process identification stays, rewritten as Condr's own table for the supported agents, because it names the agent, provides `Unknown`, and clears the state on exit. When the table sees a foreground job it cannot name (a launcher such as `mise exec -- claude`, a wrapper script) the agent's own events name it instead; a bare shell still clears it.

See `docs/research/agent-hook-status-feasibility.md` for the survey behind this decision, including tty7, whose design this follows.
