# Session Snapshots Restore Structure Only

`murmur-server` persists the authoritative `SessionSnapshot`, including stable identities, names, order, active selections, focus history, split layout and ratios, Pane cwd, and explicit Worktree Association. A Snapshot never contains terminal cells or scrollback, commands, process state, Agent state or conversations, derived Git metadata, client control state, event cursors, or Pane zoom.

The Snapshot schema stores every Pane split layout as a bounded flat root-and-node-index table instead of a recursive wire structure. The codec rejects payloads over 8 MiB and bounds one Snapshot to 64 Workspaces, 256 Tabs, 1,024 Panes, 2,047 layout nodes, and a layout depth of 64. Restore validates indices, cycles, duplicate references, reachability, Pane membership, stable identifiers, and counters before rebuilding the domain tree or starting any PTY. A persistent Server applies the stricter durable budget of one 2 MiB protocol frame minus 64 KiB of header headroom; an over-budget durable mutation is rejected before changing the authoritative Session, and an over-budget stored Snapshot is ignored at startup. Murmur is still unreleased, so the final schema and all repository clients replace the old shape atomically while both Snapshot and wire protocol version constants remain 1; there is no migration or compatibility path.

The Bootstrap header contains identity, epoch, sequence, and the structural Snapshot only. Live Terminals, Agents, derived Workspace Git metadata, and zoom state are encoded as generic `BootstrapRecord` values, each limited to 32 MiB, with a 64 MiB aggregate limit, and split into chunks that fit the 2 MiB frame limit. Capturing a Bootstrap copies instance-scoped cwd probes under the Session lock, performs OS/PID inspection after releasing it, validates the observations against the instance identities, and then holds the lock only long enough to copy structure and lightweight Terminal view sources. VT materialization and encoding also happen after releasing it. Initial handshake writes the header and batches in order. An established client is fenced while its complete reliable Bootstrap batch is prepared, so reliable events raised concurrently are queued after that batch and visual baselines advance only after enqueue succeeds. The Client validates identity, ordering, counts, chunk continuity, per-record and aggregate size, and duplicate identities, then atomically replaces its state only after the complete Bootstrap is assembled. Oversized live Pane terminal frames use bounded chunks sent as independently preemptible wire frames from one discardable visual generation, allowing reliable messages to take priority between frames. VT extraction limits each `TerminalCell` to 256 UTF-8 bytes at a character boundary while retaining its base character. GUI connection attempts carry a generation; superseded or explicit disconnects send `Detach`, and a replacement connection retries a temporarily denied control acquisition within its generation, so delayed old-client release cannot leave it permanently read-only. A rejected or gapped reliable event cursor disables mutations, requests one authoritative Bootstrap, and resubscribes; ordinary layout or visual resynchronization keeps the existing subscription and the Bootstrap-established visual baseline. A changed Server/runtime/Session authority clears the old control grant and acquires control for the new identity. Generic server errors do not trigger cursor recovery.

Each persistent Server owns one Snapshot path and holds an adjacent single-writer lock for its lifetime. Normal durable Session changes replace one pending Snapshot and reset a short debounce deadline. The worker serializes outside the Session lock and atomically replaces the target through a same-directory temporary file. Shutdown first rejects new writes and resizes, removes the runtimes from authority, samples live cwd, and keeps the PTY reader active while stopping the complete PTY session or ConPTY descendant tree with bounded escalation. It then drains and joins PTY I/O before merging tail output and scheduling the final structural Snapshot. Unix PTY reads and nonblocking writes have independent cancellation channels, so a descendant retaining the slave or a foreground process not reading stdin cannot make shutdown wait forever; process discovery and every signal validate process birth identity before acting. Ordered terminal input uses a bounded queue and byte budget, while terminal protocol replies have reserved queue capacity that user input cannot consume. Resize requests are validated synchronously and use an independent latest-wins control slot; a failed resize worker stops accepting requests, so input backpressure or a dead worker cannot leave a false pending size. The Client records a resize as pending only after the command is actually queued, clears suppression when a connection generation or authoritative Bootstrap changes, and retries from rendered geometry when synchronization or a replacement runtime requires it. Persistence bypasses the debounce, retries transient replacement failures for a bounded interval, reports a final error, and releases the Snapshot lock after the tail flush. Local default paths append `.snapshot` to the complete endpoint name; an explicit path may be supplied through server configuration or `--snapshot`. A TCP endpoint using an OS-assigned port is ephemeral unless an explicit Snapshot path is supplied because it has no stable address-derived identity.

Startup treats a missing Snapshot as an empty Session. Empty, unreadable, oversized, corrupt, trailing-data, unsupported-version, or structurally invalid Snapshots are ignored as a whole and produce Start Page state. A valid Snapshot is restored strictly, then each saved worktree association is revalidated against the current parent and child Git topology; an invalid association is cleared and the repaired Snapshot is persisted before it can grant deletion authority. Every surviving Pane starts a fresh ordinary shell in its saved cwd. An absent saved cwd uses the stable Workspace Root Directory without rewriting the optional field; an unusable saved cwd falls back to that Root Directory and persists the repair. Only a Pane that cannot start in either location is removed through the existing Pane-to-Tab-to-Workspace close cascade. Restorable siblings survive and the repaired structure is persisted. Git metadata is rediscovered. The replacement Server always has a new runtime epoch, an empty event history, and no restored Agent or terminal state.

The Server refreshes durable Pane cwd from the live Terminal runtime before cwd-inheriting layout commands, bootstrap, worktree removal, and final shutdown persistence, and folds the same refresh into the existing low-frequency Agent scan. The OS/PID probes for these paths run outside the global Server state lock and are committed only if their Terminal instance is still live and current. Unix prefers a foreground process-group member whose cwd differs from the shell, then the group leader, a terminal-reported cwd, and the shell process cwd. Linux Bash sources the user's ordinary `.bashrc` through an injected rc file and reports OSC 9;9 from an EXIT trap, making a normal `cd DIR; exit` tail durable while preserving the prior EXIT handler and status. Other Unix shells, an `exec` replacement, and forced `SIGKILL` retain the last observed cwd rather than claiming an exact exit-tail guarantee. PowerShell reports cwd through a prompt hook using OSC 9;9 while also synchronizing the process cwd; Windows then falls back to the shell process. Every accepted OSC report advances a generation. A close-time report overrides the pre-close process observation only when that generation advances while the reader is joining; otherwise each platform keeps its normal probe priority. Every successful observation replaces a last-known cwd initialized from the Terminal startup directory, so a transient lookup failure or process exit does not overwrite a newer directory. Cwd field retrieval is restricted to candidate PIDs; the existing rate-limited process inventory is reused only to locate foreground-group members. Divider/layout commands that do not inherit cwd perform no process lookup. A cwd-only update schedules persistence without publishing a reliable layout event because it does not change the Client-visible layout. The current cross-platform `bincode` representation of `PathBuf` requires UTF-8; when a Unix Terminal reports a non-UTF-8 cwd, the Server rejects only that Pane's observation, retains its last durable cwd, and still commits valid sibling observations from the same refresh.

Managed worktree removal temporarily detaches and stops that Workspace's live Terminal runtimes before invoking Git, with a runtime-only terminal instance identity preventing stale monitor threads from touching replacements. A retained authoritative view covers the short closing window without inventing a durable exit. If Git removal fails after preparation, the Workspace remains authoritative and fresh shells are started for its still-live Panes at their saved cwd and size; if a replacement shell also fails, the Pane keeps its final view as an exited runtime instead of becoming structurally detached. Prepared worktree creation failures and authority/shutdown cancellation report cleanup failures instead of silently leaving an untracked checkout.

This follows Herdr v0.8.2's structural Snapshot, atomic replacement, fresh-shell restore, and partial pruning model: a cold restart restores shape, cwd, focus, and ordering but starts new shells. Murmur deliberately excludes Herdr's optional terminal history and native Agent resume paths because the embedded agent CLI remains the owner of conversations and live process behavior. A live Client reconnect is separate: it bootstraps the still-running Server's authoritative VT and Agent state without using durable restoration.
