# A Supervisor Restarts a Crashed Server

Status: accepted 2026-11-02. Builds on ADR 0053, whose abort it recovers from, answering its "has no one to start it until Server autostart lands"; ADR 0057, whose service managers only start the Server; and ADR 0031, whose desktop-shell parent the Supervisor takes in the Server's place. Detecting a Server that hangs rather than exits was considered and left out.

A poisoned Server lock aborts the Server (ADR 0053). Its Panes' programs end with it, and the Session comes back from the Snapshot with its Agent Conversations resumed once something starts a new Server (ADR 0005). Locally, the GUI's reconnect does that. A Device reached only over TCP, Peer-to-peer or from the Companion has no one to do it, and ADR 0057's service managers only start the Server at login. Condr now starts every local Server through a Supervisor, which starts it again when it crashes.

`spawn_server`, the one place a local Server is spawned, starts a hidden `condr server supervise` instead of `condr server run`, with the same arguments. The Supervisor takes over the detaching `spawn_server` did for the Server: `setsid` on Unix, and `DETACHED_PROCESS` with the desktop shell as its parent on Windows. It then runs `condr server run` as its own child and waits for it. `spawn_server` still waits until the Server answers on its socket. So the GUI, `condr server start` and `restart`, the SSH bridge, the restart helper and the login item of ADR 0057 all get one, and nothing that waits on them changes. The Supervisor resolves the executable once (`resolve_server_executable`) and starts that path every time. `current_exe` would not do: once an update has replaced the binary, Linux reports it as `condr (deleted)`. A Server restarted after a crash therefore runs the newest installed build. The Supervisor holds no Session state and starts no threads. If it ends for any reason, the Server it started keeps running, just without a Supervisor.

How the Server ended decides what the Supervisor does:

| The Server | The Supervisor |
| --- | --- |
| exits with 0: `condr server stop`, or the old Server of a restart | exits |
| exits with the dedicated code that says another Server holds the endpoint | exits |
| on Unix, is ended by SIGTERM, SIGKILL, SIGINT or SIGHUP: shutdown, `kill`, `systemctl --user stop` | exits |
| exits in any other way: SIGABRT from ADR 0053's abort, another crash signal, a non-zero code | waits one second, then starts it again |

After four restarts within 60 seconds, a fifth crash is not restarted: the Supervisor logs that it gave up and exits. These are Syncthing's numbers. Every restart restores the Panes and resumes their Agents, so a Server that crashes at startup must not do that forever. Windows has no signals to tell a kill from a crash. So there, any exit other than 0 or the dedicated code counts as a crash. Ending `condr.exe` in Task Manager (exit code 1) starts it again; `condr server stop` is how to stop it.

Condr's own restarts stay as they are. The GUI's Restart makes the Server start `condr server restart` as its child and then exit with 0, which ends the Supervisor. The helper waits for the old Server to finish and spawns a new Supervisor through `spawn_server`. `condr server restart` from a terminal and `condr server install --restart` stop the Server, which also ends its Supervisor, and spawn a new one. So no restart needs to tell the Supervisor anything. A GUI that reconnects during the Supervisor's one-second wait may start its own Server. Whichever binds first serves. The other `server run` finds the bind lock held and exits with the dedicated code, so its Supervisor exits too.

A crash should not pass unseen. The Supervisor logs each restart to the Server's stderr log, and hands the new Server how the old one ended, its exit code or signal, in an environment variable. The new Server records that as a recent error, so `condr server status` and the GUI show that the Server restarted after a crash.

The Supervisor is `condr.exe` too, so on Windows it keeps that file in use for a moment after the Server exits. Setup upgrades by running `condr server stop` and then replacing `condr.exe`, and `condr server uninstall` deletes it. If either finds the Supervisor still running, the file is locked. The Supervisor therefore holds a lock file of its own beside the Server's bind lock, and `wait_for_shutdown` waits for both.

Letting the service managers of ADR 0057 restart the Server, as VS Code's tunnel service does with `Restart=always` and `KeepAlive`, was rejected. It would cover only the Server they started, not one started by the GUI, an SSH Client or a person. Every restart and start path would have to go through `systemctl` and `launchctl`, because a service manager that sees its process exit cleans up after it and takes the restart helper with it. Windows would still need a Supervisor of its own, since a login item supervises nothing. Syncthing ships its own monitor process for the same reasons and lets a systemd unit only start it. A switch to turn the Supervisor off, like Syncthing's `--no-restart`, was left out until someone needs it. Tests that need a bare Server run `condr server run` directly.

Consequences: each machine runs one more small process. A crash still ends every Pane's programs and any turn in progress, as ADR 0053 accepted. Only the wait before Condr comes back is shorter. A Server that deadlocks without exiting is not restarted, since the Supervisor sees only exits.

Tests: the choice between restarting, exiting and giving up is a pure function of how the Server ended and when the earlier restarts happened. It is tested with Unix signals, Windows exit codes and the 60-second window. On Unix, integration tests cover a Supervisor's whole cycle: a Server started through `spawn_server` and sent SIGABRT answers again under a new Runtime Epoch and reports the crash as a recent error; one sent SIGTERM stays down; after `condr server stop` both locks are free; and a Server that aborts at every start stops being restarted after the fifth crash. On Windows, Setup's upgrade with a Server running is checked by hand.
