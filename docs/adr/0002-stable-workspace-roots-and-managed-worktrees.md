# Stable Workspace Roots and Managed Worktrees

Condr keeps each Workspace Root Directory stable instead of deriving its identity from a live Pane cwd. A Root Directory is an absolute path interpreted and validated by the owning Server: the GUI uses a native directory picker for a local endpoint and, for a remote one, a Server-path field over the subdirectories of whatever it names, which the Server lists on request (`BrowseDirectory`: plain filesystem reads, the home directory when the path is empty, the parent named by the Server because a Client cannot split another platform's path) so a click enters one and ".." goes up. Git metadata is optional and derived, while permission to remove a checkout comes only from explicit Managed Worktree state created by Condr. Close Workspace affects runtime state only; Remove Worktree is separate, refuses dirty or untracked files, and does not delete the branch. A Managed Worktree is created at `<repo>.worktrees/<branch>` beside its repository, so it stays on the same volume and in plain sight rather than under a hidden per-user data directory; `[server] worktree_root` in the Server's `config.toml` overrides that: an absolute path or one under `~` gathers every repository's checkouts as `<root>/<repo>/<branch>`, as Herdr, Conductor and the Codex app do by default, while a relative path is resolved against each repository and holds `<repo>/<root>/<branch>`, so `..` gives git's classic sibling checkout and `.worktrees` keeps them inside the repository. This gives folder-oriented GUI identity and conservative deletion semantics at the cost of not following Herdr's dynamic identity, parent-group close cascade, or forced worktree removal.
