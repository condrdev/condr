# The Preview and Diff Tabs Highlight with syntect

Status: accepted 2026-09-29. Supersedes the grammar sentences of ADR 0017 (the `diff` tree-sitter grammar) and ADR 0018 (every grammar GPUI Kit ships).

The Preview and Diff Tabs keep GPUI Kit's read-only `Editor`. Its `InputHighlighter` seam now gets Condr's own highlighter, `condr-gui/src/app/syntax.rs`. That highlighter runs the Sublime syntaxes the bat project curates, as the `two-face` crate packages them, through syntect on Oniguruma. Condr no longer compiles any tree-sitter grammar.

The grammars were 34.8 MB of the 72.7 MB `condr-gui.exe` (`docs/research/release-binary-size.md`); the two-face set is about 1 MB. Maturity decided between the replacements. syntect and two-face are what bat and delta run on. Two options that run VS Code's TextMate grammars were declined. giallo is EUPL-1.2, reports only theme colours rather than scopes, and keeps no per-line state. ferroni with ferriki-textmate is pure Rust with VS Code grammars and per-line state, but ferriki was published the day before this decision. Oniguruma is used instead of fancy-regex because syntect measures it at twice the speed and the syntaxes are written for its regex semantics. It is C, built with `cc` from the sources it bundles and without bindgen, which the build already needs.

Colours come from TextMate themes, through syntect's own scope-selector matching, not from Kit's highlight theme. Kit's default colours were plain, and its 41 highlight names would have flattened the themes' scope rules. Condr offers eight families, not the three dozen two-face bundles, with a light and a dark variant wherever one exists: GitHub, Dracula, Gruvbox, One Half, Tokyo Night, Solarized, Nord and JetBrains. The list is sorted by name. Dracula and Nord have no light variant: Dracula's Alucard is announced but ships no tmTheme yet, and Nord has none. Gruvbox, One Half, Solarized, Dracula and Nord come from two-face. The other six are vendored as tmTheme files in `crates/condr-gui/assets/code_themes`, which syntect's `plist-load` reads (the `plist` crate was already in the build through iroh). `script/generate-code-themes.mjs` writes them from pinned upstream revisions. Tokyo Night is copied unchanged from folke/tokyonight.nvim's tmTheme extras. GitHub Light and GitHub Dark are converted from GitHub's own VS Code themes, as Shiki redistributes them; bat's "GitHub" is an older light-only look. JetBrains Light and JetBrains Darcula are converted from the IntelliJ Light and Darcula editor schemes in intellij-community, because the Darcula tmThemes published elsewhere carry no license. The script resolves each scheme's inheritance and maps about twenty IntelliJ attributes, such as `DEFAULT_KEYWORD` and `DEFAULT_STRING`, onto TextMate scopes. Diffs take the IDE's file-status colours.

Settings > Appearance > Syntax has one Highlight theme choice (`[client.code] theme`), a searchable Select like the terminal's Colors. Default, stored as an empty name, paints with GitHub Light in a light GUI and GitHub Dark in a dark one. A named theme holds in both modes, and after switching modes the user picks another if it no longer suits. Kit still draws the selection, the caret and the line numbers in the GUI's colours, so a dark theme in a light GUI shows them as the light GUI would. The same group has a Font size (`[client.code] font_size`), apart from the terminal's; both start at the theme's mono font size, and the Tabs keep the terminal's font family. The chosen theme also becomes the background of the Preview and Diff Tabs and of Kit's code-editor gutter and current line. Changing the GUI mode resets Kit's highlight theme, and Default depends on the mode, so the code theme is applied again after every mode change. That is the only part of Kit's global theme this touches, and nothing else in the GUI uses a code editor. A parse records each range's scope stack and never a colour. A theme change therefore recolours on the next paint without parsing again: styles are resolved per stack the first time painting needs one. Text without a scope style takes the theme's foreground, since Kit would otherwise draw it in the GUI's. Text colours ignore a theme's alpha, as bat does; gruvbox gives its foreground half of it.

Every refresh of a read-only Editor reaches the highlighter as a whole-document edit. It compares the old and new text and keeps the colours on the unchanged start and end until the new parse lands, so an agent editing the shown file does not blank them (ADR 0018). Each parse starts from the top of the text and runs on a background thread, and a newer update cancels it. On this laptop a 1 MiB Rust file takes about 0.8 s and TypeScript about 1.6 s. Markdown lines with many inline spans can take tens of milliseconds each. Lines over 10,000 bytes stay plain, as they do in Kit's own painting. The UI thread only loads the syntax set, about 30 ms, the first time a highlighted Editor opens.

The costs are accepted. The syntaxes are older than the tree-sitter grammars. bat pins `sublimehq/Packages` at `759d6ee`, whose Rust syntax does not know `async`, `await` or `dyn`, and syntect cannot load the newer Sublime syntax format that fixes it. Astro and EJS files lose highlighting, while SQL, XML, PowerShell, Dockerfile and Makefile gain it. Nothing gives fold ranges, which neither Editor uses. The licenses of the syntaxes and themes, all permissive, are in `crates/condr-gui/assets/NOTICE-HIGHLIGHTING` and `crates/condr-gui/assets/code_themes/NOTICE`, and reach Settings > Licenses through `script/generate-licenses`.

Two changes would reopen this. If large files that agents keep editing make the full reparse visible, the highlighter can cache a syntect `ParseState` every few hundred lines and resume from the one before the change. If a VS Code-grammar engine such as ferriki matures, it fits behind the same seam. The theme settings would carry over, since it resolves TextMate scopes against TextMate themes too.
