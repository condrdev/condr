# One Rust Client Library Serves the GUI and the Companion

Status: accepted 2026-10-10. Moves `Endpoint` dialling and the Device key out of `condr-server`, which ADR 0022 placed there; changes why ADR 0026 says the GUI carries iroh; replaces ADR 0028's expectation that Swift and Kotlin Clients generate their own types from the `.proto` files.

The Companion, Condr's iOS and Android app, gets its Client logic from the same Rust code as the desktop GUI, through exactly one library per platform. `condr-core` gains a `runtime` feature, on by default, behind which everything that needs a PTY, a VT, Git or the process table sits. A new crate, `condr-client`, holds everything a Client does with a Server short of drawing it: the Device key and Noise, `ClientConnection`, dialling `tcp://` and `p2p://`, and the read model the GUI keeps today. A second new crate, `condr-mobile`, is the uniffi layer over `condr-client` and the only Rust library either app links. The apps live in `mobile/ios` (SwiftUI, iOS 17 and later) and `mobile/android` (Jetpack Compose, API 29 and later), beside `website/`, each with its own toolchain and workflow. iOS comes first; the library builds for both platforms from the start, so nothing iOS-only settles into it.

Decoding messages is the easy part of a Client. The hard parts are the Noise handshake with its Ed25519 payload (ADR 0025), the iroh endpoint (ADR 0026), Bootstrap assembly, and the chunk assembly, delta merge and resync the coalesced visual stream needs (ADR 0004), together with `AgentTracker`, which turns an unseen `Idle` into Done. ADR 0028 expected a Swift or Kotlin Client to generate its types from the `.proto` files; that would have meant writing all of those parts twice more, in two languages, and fixing each bug three times. The `.proto` files stay the wire contract and the version range applies to the Companion as to any Client, which is what a build waiting days in store review needs. iroh's own Swift and Kotlin bindings (`iroh-ffi`) are not used either, because each platform links one Rust library and no more. Rust static libraries export their copies of the standard library's and the allocator's internal symbols, so two of them built with the same toolchain collide at link time on every platform (rust-lang/rust#104707), and two uniffi frameworks in one Swift target collide on the `RustBuffer` C type (uniffi-rs#2802). Mozilla's answer is one library holding every crate, its "megazord"; `condr-mobile` is that. `iroh-ffi` 1.1 also ships an Android library that fails Google Play's 16 KB page-size check and pins a `netdev` that references an iOS 26-only symbol; Condr's own lock resolves `netdev` 0.46.3, which no longer does, on Apple targets.

The protocol layer uses types that are defined in the same files as runtime code: `git/changes.rs` defines the change and diff types and then `impl GitRepository` over gix, `terminal/view.rs` defines `TerminalView` beside its alacritty glue and the `PtySize` conversion, `terminal/input.rs` defines `TerminalCommand` beside the encoders that read alacritty's `TermMode`, `agent/hooks.rs` defines the hook report types beside the installer, and `files.rs` defines listings beside `browse_directory`. Each such file splits into a file of types and a file of runtime code, and `runtime` gates the runtime files at their `mod` line, never item by item. With the feature off, `condr-core` is the protocol, the Session and its Snapshot, the terminal view and command types, the Agent types including `AgentTracker`, and the build identity, and it builds without gix, `alacritty_terminal`, `portable-pty`, `sysinfo`, `nix` or `toml`. `condr-server` keeps the default; `condr-client` and `condr-mobile` take `default-features = false`. A separate protocol crate was declined: it needs the same file splits, then four rewrites that Rust's coherence rules force (`impl Dimensions for TerminalSize`, `impl From<TerminalSize> for PtySize`, `impl From<CursorShape> for TerminalCursorShape`, `TerminalMouseTracking::from_term_mode`), and `AgentKind::spec()` would drag the hook installer formats across; `docs/code-organization.md` adds crates for responsibilities, not for file splits. A crate boundary would have the compiler hold the line; here CI does, by checking `condr-core` without default features for the iOS and Android targets on every pull request.

`condr-client` takes from `condr-server` the key types (`DeviceKey`, `PublicKey`, `Secret`), `NoiseStream` in both roles, so the Server takes its responder from here, `ClientConnection`, the parsing and dialling of `tcp://` and `p2p://` addresses, and `P2pNode`. `P2pNode` bridges iroh's async API to blocking reads and writes with `Handle::block_on`; it takes the handle from its owner, the Server's runtime on the desktop and one small multi-thread runtime that `condr-mobile` creates. It takes from `condr-gui` what has no GPUI type in it: the reader and writer threads of `ClientIo` with their heartbeat, `connection/terminal_frames.rs`, the validated Session read model of `server_connection.rs`, the driving of `AgentTracker`, and the "Needs you" filter that `sidebar.rs` runs today, which becomes a function over the connections that the sidebar renders. The GUI keeps the hop from those threads into its executor and everything it draws. What only a desktop does stays in `condr-server`: the local socket and its listener, SSH, the `Tunnel` fallback that starts a local Server for a Peer-to-peer address, the identity store with `authorized-clients` and invites, `[[client.servers]]` in `config.toml`, and `device_name()` read from the host name. The desktop `Endpoint` enum stays there too and hands its TCP and Peer-to-peer variants to `condr-client`. `condr-core` still knows no remote machine (ADR 0022), and the GUI still carries iroh (ADR 0026), now because it depends on `condr-client`.

`condr-mobile` is a thick library. It holds one connection per paired Device, their read models, an `AgentTracker` fed by what the Companion has on screen, and the "Needs you" list across Devices. It exposes, through uniffi 0.32 proc macros, one foreign trait the app implements, whose only method is `changed(scope)` and carries no data, called from one notifier thread; synchronous getters that return view models (Devices, their Workspaces and Agents, "Needs you", one Pane's current terminal view); synchronous commands that enqueue and return (terminal input, scroll, selection, focus, size, which Panes to stream); and an explicit `close()`. The app answers `changed` by hopping to its main thread and pulling what it shows. This is the GUI's own pattern, `cx.notify()` and then a read of current state, and it keeps the property the terminal depends on (AGENTS.md): the latest state wins, so a burst of frames while an Agent animates costs one pull, never a queue of stale views. On Android, JNA attaches a thread to the JVM on every call it did not attach permanently; one long-lived notifier thread is one attachment. Two alternatives were declined. An exported `async fn next_event()` wrapped into an `AsyncSequence` and a `Flow` makes events a queue again, and uniffi's async support is uneven where a connection needs it: cancelling a Swift `Task` does not cancel the Rust future, and running tokio under it goes through `async-compat`, whose runtime Matrix had to fork to configure. Passing every event's data through the listener queues all of them on the main thread, which is the backlog ADR 0004 removed.

`script/build-mobile.sh ios|android` builds the library and its bindings. For iOS it builds the device and simulator targets, generates the Swift file, header and module map with `uniffi-bindgen-swift`, and assembles an xcframework with `xcodebuild -create-xcframework`, which `mobile/ios` consumes through a local Swift package. For Android it builds with `cargo-ndk`, links with `-z max-page-size=16384` for Play's 16 KB requirement, generates the Kotlin bindings, and fills a Gradle library module in `mobile/android`. Xcode runs the script in a pre-build phase and Gradle in `preBuild`, so an app build never links a stale library, and Cargo's incremental build makes the unchanged case cheap. Neither the built library nor the generated bindings are committed. Matrix, Bitwarden and `iroh-ffi` each keep a hand-written build like it; `cargo-swift` does not support uniffi 0.32 yet. The library is static and linked into the app alone. `ci.yml` checks `condr-core` without default features and builds `condr-mobile` for `aarch64-apple-ios` and `aarch64-linux-android` on every pull request, since a protocol change that breaks the library breaks both apps; a `mobile.yml` triggered by `mobile/**` and `crates/**` builds the apps, as `website.yml` owns `website/`, and `ci.yml` ignores `mobile/**`. AGENTS.md's layout and `docs/code-organization.md` change with the implementation.

Left for later, each with its trigger: a dynamic framework shared by the app and its Notification Service Extension, as Element X ships, when the push ADR decides the extension runs Rust, since two static copies double the size and the extension lives within about 24 MB; publishing the library as a Swift package or Maven artifact, when something outside this repository wants it; uniffi's async exports, if a later uniffi propagates Swift cancellation and needs no runtime shim.

Tests: `condr-core` built without `runtime` for both mobile targets in CI; the tests of every moved file moving with it, so the handshake, Noise in both roles, Bootstrap assembly, frame merge and resync keep running headless in the workspace; a `condr-mobile` test driving its listener against an in-process Server, where a burst of terminal frames produces one `changed` per notifier wake and the pulled view is the latest revision; a Peer-to-peer dial from `condr-client` to a Server over loopback with `RelayMode::Disabled`, the setup ADR 0026 uses.
