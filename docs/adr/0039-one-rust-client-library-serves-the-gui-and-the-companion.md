# One Rust Client Library Serves the GUI and the Companion

Status: accepted 2026-10-10. Moves `Endpoint` dialling and the Device key out of `condr-server`, which ADR 0022 placed there; changes why ADR 0026 says the GUI carries iroh; replaces ADR 0028's expectation that Swift and Kotlin Clients generate their own types from the `.proto` files.

The Companion, Condr's iOS and Android app, gets its Client logic from the same Rust code as the desktop GUI, through exactly one library per platform. `condr-core` gains a `runtime` feature, on by default, behind which everything that needs a PTY, a VT, Git, the process table or the desktop's files sits. A new crate, `condr-client`, holds everything a Client does with a Server short of drawing it: the Device key and Noise, both ends of the TCP and Peer-to-peer transports, `ClientConnection`, and the read model the GUI keeps today. A second new crate, `condr-mobile`, is the uniffi layer over `condr-client` and the only Rust library either app links. The apps live in `mobile/ios` (SwiftUI, iOS 17 and later) and `mobile/android` (Jetpack Compose, API 29 and later), beside `website/`, each with its own toolchain and workflow. iOS comes first; the library builds for both platforms from the start, so nothing iOS-only settles into it.

Decoding messages is the easy part of a Client. The hard parts are the Noise handshake with its Ed25519 payload (ADR 0025), the iroh endpoint (ADR 0026), Bootstrap assembly, and the chunk assembly, delta merge and resync the coalesced visual stream needs (ADR 0004), together with `AgentTracker`, which turns an unseen `Idle` into Done. ADR 0028 expected a Swift or Kotlin Client to generate its types from the `.proto` files; that would have meant writing all of those parts twice more, in two languages, and fixing each bug three times. The `.proto` files stay the wire contract and the version range applies to the Companion as to any Client, which is what a build waiting days in store review needs. iroh's own Swift and Kotlin bindings (`iroh-ffi`) are not used either, because each app links one Rust library and no more. A Rust static library exports its copies of the standard library's and the allocator's internal symbols, so two of them in one binary can clash at link time or silently override each other (rust-lang/rust#104707), and two uniffi frameworks in one Swift target collide on the `RustBuffer` C type (mozilla/uniffi-rs#2802). Mozilla's answer is one library holding every crate, its "megazord"; `condr-mobile` is that. `iroh-ffi` 1.1 also ships an Android library that fails Google Play's 16 KB page-size check (n0-computer/iroh-ffi#279), and its lockfile pins `netdev` 0.45, older than the 0.46.1 release that dropped a reference to an iOS 26-only symbol; Condr's own lock resolves `netdev` 0.46.3 on every target but Windows.

The protocol layer uses types that are defined in the same files as runtime code: `git/changes.rs` defines the change and diff types and then `impl GitRepository` over gix, `terminal/view.rs` defines `TerminalView` beside its alacritty glue and the `PtySize` conversion, `terminal/input.rs` defines `TerminalCommand` beside the encoders that read alacritty's `TermMode`, `agent/hooks.rs` defines the hook report types beside the installer, and `files.rs` defines listings beside `browse_directory`. Each such file splits into a file of types and a file of runtime code, and `runtime` gates the runtime files at their `mod` line, never item by item. Whole modules go behind it too: `terminal/view/snapshot.rs`, which is alacritty glue throughout, while `terminal/view/wire.rs` is protocol and stays; `config.rs` and `paths.rs`, since a phone has neither `config.toml` nor a data directory; and the PTY, process, Job Object and shell modules. With the feature off, `condr-core` is the protocol, the Session and its Snapshot, the terminal view and command types, the Agent types including `AgentTracker`, and the build identity. It builds without gix, `alacritty_terminal`, `portable-pty`, `sysinfo`, `nix`, `filedescriptor`, `toml`, `toml_edit`, `atomicwrites`, `dirs`, `windows-sys` or `core-foundation-sys`, and CI holds that line, by checking `condr-core` without default features for the iOS and Android targets on every pull request. `condr-server` keeps the default; `condr-client` and `condr-mobile` take `default-features = false`. A separate protocol crate was declined. It needs the same file splits, then four rewrites that Rust's coherence rules force (`impl Dimensions for TerminalSize` and `impl From<TerminalSize> for PtySize` in `view.rs`, `impl From<CursorShape> for TerminalCursorShape` in `view/snapshot.rs`, and `TerminalMouseTracking::from_term_mode`), and `AgentKind::spec()` would drag the hook installer formats across; `docs/code-organization.md` adds crates for responsibilities, not for file splits.

`condr-client` owns both ends of the two remote transports, so a phone and a Server run the same handshake code. From `condr-server` it takes the key types (`DeviceKey`, `PublicKey`, `Secret`), `NoiseStream` as initiator and responder, `P2pNode` with its bind, dial, accept and stream, the `Credential` frame, `ClientConnection`, and the parsing of `tcp://` and `p2p://` addresses. Today the responder and the accepting side of `P2pNode` hold `ServerIdentity` directly, to check a peer, read the pending invite, record a pairing and note when a Device was last seen; in `condr-client` they hold a small trait with those four operations instead, which `condr-server` implements with `ServerIdentity`. The authorized list, invites and their files stay with the Server, and the phone, which accepts nothing, never builds that half. `condr-client` defines its own stream for the two transports; `condr-server`'s `EndpointStream` wraps it and adds the local socket, SSH and `Tunnel`, and the desktop `Endpoint` enum does the same for addresses. `P2pNode` bridges iroh's async API to blocking reads and writes with `Handle::block_on`, and takes the handle from its owner: the Server's runtime on the desktop, one small multi-thread runtime that `condr-mobile` creates on a phone. From `condr-gui` it takes what has no GPUI type in it: the reader and writer threads of `ClientIo` with their heartbeat, `connection/terminal_frames.rs`, the validated Session read model of `server_connection.rs`, the driving of `AgentTracker`, and the "Needs you" filter `sidebar.rs` runs today, which becomes a function over the connections that the sidebar renders. The GUI keeps the hop from those threads into its executor and everything it draws. What only a desktop does stays in `condr-server`: the local socket and its listener, SSH, the `Tunnel` fallback that starts a local Server for a Peer-to-peer address, the identity store, `[[client.servers]]` in `config.toml`, and `device_name()` read from the host name. `condr-core` still knows no remote machine (ADR 0022), and the GUI still carries iroh (ADR 0026), now because it depends on `condr-client`.

`condr-mobile` is a thick library. It holds one connection per paired Device, their read models, an `AgentTracker` fed by what the Companion has on screen, and the "Needs you" list across Devices. Through uniffi 0.32 proc macros it exposes one foreign trait the app implements, whose only method is `changed()` and carries no data; `take_changes()`, which returns the scopes that changed since the last call (a Device, a Workspace, "Needs you", a Pane's terminal); synchronous getters that return view models for those scopes; `take_events()`, which drains a bounded queue of one-time results in order; synchronous commands that enqueue and return (terminal input, scroll, selection, focus, size, which Panes to stream); and an explicit `close()`. The app answers `changed` by hopping to its main thread, calling `take_changes()` and pulling what it shows. The library calls `changed` again only after `take_changes()` has run, however many changes arrive meanwhile, the way the GUI's `TerminalVisualSlot` stays signalled until the UI takes it; a change that lands during the pull marks its scope for the next round, so the last one is never lost. This is the GUI's own pattern, `cx.notify()` and then a read of current state, and it keeps the property the terminal depends on (AGENTS.md): the latest state wins, so a burst of frames while an Agent animates, or a main thread stalled for a second, costs one pull, never a queue of stale views or of refreshes. What is not state goes through `take_events()`: a failed operation, as one error the app shows and lets the person copy (ADR 0020), each delivered once and in order; the text a `Copy` returned; and OSC 52 clipboard writes, of which only the newest waiting one is kept (ADR 0007). Nothing in that queue survives a reconnect, so no clipboard write is ever replayed. The notifier is one long-lived Rust thread; on Android it attaches to the JVM permanently when it starts, since otherwise JNA attaches and detaches it on every call. The callback never blocks on the main thread and is never made while a read model's lock is held. Two alternatives were declined. An exported `async fn next_event()` wrapped into an `AsyncSequence` and a `Flow` makes state a queue again, and uniffi's async support is uneven where a connection needs it: cancelling a Swift `Task` does not cancel the Rust future, and running tokio under it goes through `async-compat`, whose runtime Matrix had to fork to configure. Passing every event's data through the listener queues all of it on the main thread, which is the backlog ADR 0004 removed.

`script/build-mobile.sh ios|android` builds the library and its bindings. For iOS it builds a static library for the device and simulator targets, generates the Swift file, header and module map with `uniffi-bindgen-swift`, and assembles an xcframework with `xcodebuild -create-xcframework`, which `mobile/ios` consumes through a local Swift package and links into the app alone. For Android it builds `libcondr_mobile.so` per ABI with `cargo-ndk`, since JNA loads a shared library at run time, links it with `-z max-page-size=16384`, generates the Kotlin bindings, and fills a Gradle library module in `mobile/android`; Android's build acceptance checks the final APK and app bundle against Play's 16 KB page requirement, JNA's own native library included. One aggregate library per platform holds either way. Xcode runs the script in a pre-build phase and Gradle in `preBuild`, so an app build never links a stale library, and Cargo's incremental build makes the unchanged case cheap. Neither the built library nor the generated bindings are committed. Matrix, Bitwarden and `iroh-ffi` each keep a hand-written build like it. `ci.yml` checks `condr-core` without default features and builds `condr-mobile` for `aarch64-apple-ios` and `aarch64-linux-android` on every pull request, since a protocol change that breaks the library breaks both apps; a `mobile.yml` triggered by `mobile/**` and `crates/**` builds the apps, as `website.yml` owns `website/`, and `ci.yml` ignores `mobile/**`. AGENTS.md's layout and `docs/code-organization.md` change with the implementation.

Left for later, each with its trigger: a dynamic framework shared by the iOS app and its Notification Service Extension, as Element X ships, when the push ADR decides the extension runs Rust, since two static copies double the size and the extension lives within about 24 MB; publishing the library as a Swift package or Maven artifact, when something outside this repository wants it; uniffi's async exports, if a later uniffi propagates Swift cancellation and needs no runtime shim.

Tests: `condr-core` built without `runtime` for both mobile targets in CI; the tests of every moved file moving with it, so the handshake, Noise in both roles, the accepting side through the authorization trait, Bootstrap assembly, frame merge and resync keep running headless in the workspace; a `condr-mobile` test that blocks its consumer while bursts of terminal frames arrive, then checks that at most one `changed` is outstanding and the pulled view is the latest revision; `take_events()` returning two errors in order, each once, keeping only the newest of two clipboard writes, and returning nothing after a reconnect; a Peer-to-peer dial from `condr-client` to a Server over loopback with `RelayMode::Disabled`, the setup ADR 0026 uses.
