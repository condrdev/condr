# Shell Integration Does What Ghostty's Does

Status: accepted 2026-11-23. Amends ADR 0055.

ADR 0055's scripts printed three marks and left the prompt string alone. Condr's VT is Ghostty's, and Ghostty's own integration does more with the same marks: it puts them into the prompt so they come back whenever the shell redraws it, marks where the input starts, reports the shell's directory and sets the cursor. Condr's scripts now do what Ghostty's do. Ghostty's zsh and bash scripts are GPLv3, derived from kitty's, so Condr's are written afresh from what they do and share no code (AGENTS.md); its fish script is MIT. Ghostty's `sudo`, `ssh-*` and `path` features serve its own terminfo and binary and are left out, and so is `title`, which would change what Condr's Tabs show.

**Prompts.** zsh and bash put the marks into PS1 and PS2 at each prompt: `133;A;cl=line` at the start of zsh's prompt, `133;P;k=i` at the start of bash's, `133;P;k=s` at the start of each further line of a multi-line prompt and of PS2, and `133;B` where the input starts. They take them out again before a command runs, bash only from 5.3, whose PS0 can run a function in the shell itself, so other hooks and the command see the prompts as the person set them; a prompt still unchanged at the next one starts again from the person's own. bash also sends `133;A;redraw=last;cl=line;aid=<pid>` before its prompt, since it redraws only a prompt's last line after a resize, or `133;P;k=i` when ble.sh runs, which tracks the cursor itself. So that the prompt marked is the one the person's own hooks set, zsh installs its hooks at the first prompt, after the person's `.zshrc`, and its precmd hook moves itself to the end of `precmd_functions` whenever another comes after it, marking that one prompt by hand; zsh hands each hook the command's own exit status. bash's call goes last in `PROMPT_COMMAND`, the status taken first. A prompt a theme rebuilt since it was marked is marked again, and one a plugin set after the hook ran gets `133;P;k=i` and `133;B` from `zle-line-init`. fish marks its prompt with `133;A`, with `click_events=1` from fish 4.1, also after a syntax error, and sets `fish_handle_reflow`, since the terminal clears the prompt on a resize. Every shell ends a command with `133;D;<status>`, bash adding its `aid`, and one whose end went unmarked with a bare `133;D` before the next prompt. libghostty-vt cannot yet tell a redrawn prompt from a new one, so each redraw is another prompt start to the Server; at a shell's prompt that changes nothing, and `133;P;k=i` counts as a first prompt for ADR 0059 as `A` does.

**Directory.** zsh reports its directory with OSC 7 in kitty's form, `kitty-shell-cwd://<host><path>` with the path as it is, at each prompt and on each `cd`; bash at a prompt whose directory changed, having no hook for a change; fish as a `file://` URI on each change. Control bytes are dropped from the host and the path, so a directory's name cannot end the sequence and start one of its own. The Server reads kitty's form beside `file://`, still only for this machine's paths.

**Cursor.** The VT's default cursor is a blinking bar: Condr sets libghostty-vt's default style and blink so, where Ghostty's default is a blinking block. zsh sets the bar (`CSI 5 q`) from `zle-line-init`, `zle-line-finish` and `zle-keymap-select`, a blinking block (`CSI 1 q`) in vi command mode, and `CSI 0 q` as a command starts; bash ends PS1 with the bar and puts `CSI 0 q` in PS0; fish sets the bar at its prompt and `CSI 0 q` before a command, and leaves both to fish's own vi mode cursor when it has one. As in Ghostty, a zsh widget the person defined runs after Condr's, while add-zle-hook-widget's list gets Condr's last, after any hook that fails and so stops it; the bar in bash's PS1 comes after anything `PROMPT_COMMAND` printed.

zsh writes the marks through a descriptor of its own on the terminal, closed in the programs it starts, so they arrive while the shell's output is redirected. Programs the shell starts still inherit none of Condr's variables, and the setting stays ADR 0055's one switch: Ghostty's switches for each feature have no counterpart.

Tests: zsh and bash report their directory and set the cursor at the prompt and for a command, zsh also in vi command mode; zsh runs the person's widgets in Ghostty's order and hands a command its prompt unmarked; the VT's default cursor blinks and DEC mode 12 still stops it; kitty's OSC 7 keeps its path as sent and refuses another host; a command's end with an `aid` keeps its exit code. The bash tests ran by hand against bash 5.3, macOS's own being 3.2, and fish's script ran by hand in a container. A resize kept the prompt whole under ADR 0055's scripts as well, so no test claims what the marks in the prompt add there.
