# Agent Status Comes From the Program Status Protocol Too

An Agent that speaks the Program Status Protocol, OSC 7501, reports its state to Condr the way it reports it to any terminal: `OSC 7501 ; state=blocked:kind=permission:app=claude-code:msg=… ST`, written to its own PTY. The Server reads those reports where it already reads the OSC 777 events of ADR 0014, and from the first one on they are the Pane's Agent state. The hooks stay installed: they are the only source of the native session ID a restart resumes with, they remain the state of every Agent that does not speak the protocol yet, and they are the fallback where the protocol's detection cannot succeed. Two states join the wire, `Done` and `Error`, and what was `blocked_on` becomes `detail`, carried by both `Blocked` and `Error`.

Within two weeks of Mitchell Hashimoto's proposal (revision 0.4, 2026-10-10) Claude Code 2.1.295, Codex 0.163, Pi 1.1, Oh My Pi 18.8.7, Grok Build 1.0.52 and Antigravity 1.4 ship it; OpenCode merged and reverted it, and Cursor, Copilot and Kimi have requests open. It is what ADR 0014 wanted from the hooks, said by the program itself with no configuration to install: the same five states Condr has or wanted, the kind of wait (`permission`, `question`, `auth`) and a one-line message, ordered with the output in the same byte stream, and working over SSH and in any shell. It also says what hooks cannot: Claude Code reports `idle` after an interrupt that fires no hook, and Pi tells a cancelled run from a finished one. What it does not carry is identity: no session ID, so ADR 0005's resume still needs the hooks' `SessionStart`.

The Server answers the protocol's feature-detection query, `OSC 7501 ; ? ST`, with a bare `?`, which promises exactly the five base states and three base kinds. Claude Code, Pi, Grok and Antigravity report only after that answer, and Claude Code and Pi send primary device attributes right behind the query and read a DA1 reply arriving first as "unsupported", so the answer is queued as the PTY scanner reads the query, before the VT parses the same chunk and queues its DA1 reply. The answer goes out whether or not a client is connected and whether or not the Pane has an Agent: the Server owns the VT. On a Windows Server conhost answers DA1 itself, ahead of anything Condr writes, so Claude Code and Pi conclude there that the protocol is unsupported and the hooks carry on as before (the kitty probe loses the same race, ADR 0035); Codex and Oh My Pi report unconditionally and are unaffected.

A report counts for the Pane's Agent as a hook event does. The process table names the Agent; a report whose `app` resolves to another agent, through the same names the process table matches, or to no agent at all, is a nested reporter's, a Codex that Claude runs or a `cargo` that learned the protocol, and is dropped; a report without `app` is the Agent's. A report naming an Agent the table cannot see through its launcher names it, as a hook does. A recognized-only Agent's reports count too: its root record is its own, which is the distinction ADR 0035 could not draw from its hooks, though its level, and with it `agent wait`'s refusal, still follows its hooks; none of them speaks the protocol today. Only the root record, the report without `id`, is the Agent; Claude Code reports each subagent and background task under its own `id`, and those records are ignored until a Pane is seen needing them. A nested agent of the same kind, a `claude` that Claude runs from a tool, carries the same `app` and is not told apart, as ADR 0014 already accepts for its hooks. `idle`, `working`, `done`, `blocked` and `error` map one to one. `detail` is the `msg` when the report has one; a `blocked` report without one gets its `kind`'s label, so a login shows as `Login`; a `done` keeps no message. `title`, `progress` and the reply's optional lists are not read.

The protocol's lifetime rules apply to the state it produced, and only to that. `state=clear` deletes the record and the Agent is `Unknown` until it reports again, which is what Codex does around an external editor; a Client reads that `Unknown` as the same process with no record, not as a new one, so a Workspace row the user folded stays folded. A new shell prompt, OSC 133 `A`, drops a `working` or `blocked` record and leaves `idle`, `done` and `error`. A full reset, `ESC c`, removes every record, and the hooks count again until the next report. Hook state ignores all three, as ADR 0014 left it: it ends with the process; and a Pane whose Agent has not reported through the protocol does not even queue them, so a plain shell's prompt marks never wake the process probe. A report with an unknown `state` is dropped whole even when a later pair repeats the key with a known one, the specification's rule for a state added later being read over its rule for repeats. Process exit clears the Agent whole, `done` and `error` included, which the protocol would keep for the user to find; Condr's Agent is a process, and every CLI that speaks the protocol writes `clear` on exit anyway. Nothing is stripped from the bytes the VT sees: vte drops the OSC it does not know, and no client receives raw output.

`Done` and `Error` are states the Agent reports, so they are on the wire, and the hooks say them too: `Stop` is `Done`, `StopFailure` is `Error`, `Interrupt` and `SessionStart` are `Idle`, the way the protocol would report the same moments, so an Agent shows the same whichever way it told Condr. What the GUI called Done, an `Idle` after work a Client did not watch, is replaced by the Agent's own `Done` and one bit of each Client's own: whether this Client looked at it. A `Done` the Client saw arrive, or whose Pane it opened since, shows as `Idle`; otherwise as `Done`; the Agent's own `idle`, once it sees the user back, clears it on every Client. Each Client still keeps its own, so an Agent watched finishing on the desktop is still Done on the phone (ADR 0041), and a Client that connects later now sees the `Done` the Agent still reports instead of `Idle`. `Error` shows until the Agent moves on, looked at or not. Codex before 0.164 reports `idle` after a turn, not `done`, so its finished turns show `Idle`; the GUI still raises its "finished" notification on an `Idle` straight after work.

`Error` needs the person as much as `Blocked` does: a failed turn does nothing until someone looks. The "Needs you" list of ADR 0024 takes both, on the desktop and the Companion, with `detail` as the second line; the OS notification says `<agent> failed` with the detail first; the Companion's Agents tab counts both in its badge. The CLI prints `done` and `error` as `agent_status`, takes them for `--until`, and `agent wait` and `agent prompt --wait` settle on `idle`, `done`, `blocked` or `error` by default, since an Agent at its prompt is what an orchestrating agent waits for; `agent prompt` accepts a prompt in any of `Idle`, `Done` and `Error`. The JSON field is `detail`. `PROTOCOL_VERSION` stays `1`, the project being unreleased; an older peer reads the two new enum values as `Unknown` (ADR 0028).

Settings › Server › Agents changes nothing: the hooks remain what Condr installs, for the session ID and for the Agents and platforms the protocol does not reach. Which CLI speaks the protocol, since which version, whether it waits for the answer, and what it sends is recorded in [program-status-emitters.md](../research/program-status-emitters.md); Pi's `PI_PROGRAM_STATUS`, Grok's `program_status` and Antigravity's `AGY_CLI_OSC7501` can force it on where a probe cannot run.

Three things were declined. Letting the two sources interleave, last report wins, is less code but makes `detail` alternate between a hook's `Bash: cargo test` and the protocol's `msg` for one wait; the protocol's own rule for OSC 9;4, stop reading the older signal once the newer one speaks, is what this decision does with the hooks' state. Dropping the hooks for Agents that speak the protocol loses resume and loses Windows. Showing any program's reports, a `brew` or a `terraform` that learned the protocol, would need a notion of program status on a Pane that is not an Agent; nothing asks for it yet.

ADR 0014 stands as the hooks' design and loses its last word on Done: "a presentation of an unseen `Idle`, not a wire state" is superseded here. ADR 0024's `blocked_on` is `detail`. ADR 0041's Companion Done keeps its per-Client nature and drops the sentence about an Agent that finished while the app was away showing as `Idle`. CONTEXT.md's Agent, Done and Needs you entries change accordingly.

Tests: the parser against the specification's own examples and every limit it fixes, a bad pair skipped and a bad report dropped whole; the scanner reporting a query, a report, a prompt start and a reset, split across reads and ended by a bare `ESC`, with the bytes reaching the VT untouched; a real PTY in which the answer to the query precedes the VT's DA1 reply; the detector taking the protocol's state over a later hook's while still taking its session ID, dropping another `app` and a child `id`, labelling a wait from its kind, keeping only `Error`'s message, applying `clear`, a prompt start and a reset only to protocol state, seeding an Agent from `app` and accepting a recognized-only Agent's root record; the hooks' new mapping; the tracker's seen bit; the CLI settling on `done`; the sidebar listing an `Error` Agent under Needs you with its detail and counting it on a folded Workspace row. Manual, on this Mac: a Claude Code 2.1.303 and a Codex 0.163 Pane going Working, Blocked with the request's text, and Done or Idle, with the hooks installed and with them removed.
