# No Session Control: the Window Last Focused Sizes the Terminals

Session control is gone. One Client used to hold an exclusive controller lease per Session (ADR 0003), and every other GUI fell into "Viewing only": it could type (ADR 0009) but not resize, scroll, select or report focus and the mouse, and it locked its own Dock and Pane menus besides. Nothing let a person take control, and the lease ended only when its holder's connection did. A stale connection therefore locked out the next one. A laptop that slept or changed networks while connected over SSH reconnected at once, but the old `condr server bridge` stayed attached to the Server's socket under an `sshd` that had not noticed its peer was gone (no `ClientAliveInterval` by default, TCP keepalive after two hours), so the new window sat in "Viewing only" for as long as that took, with nothing to click.

Every Client may now do everything. What control guarded splits into what all Clients share and what one window has to decide:

- Scroll position and the finished selection stay one per Pane in the Server's VT (ADR 0008); the last Client to change them sets them for all. Per-Client copies would need a VT view per Client, and two people reading one Pane at once is rare enough to wait for that.
- Focus reporting follows the last Client to report a focused Pane. A Client that no longer holds the focus cannot take it away with a late `Focus(false)`, and a Client that leaves loses it. The mouse button a Client last pressed is released when it leaves, as the controller's was.
- A PTY has one size. The Server remembers the Client that last reported a focused Pane, the window in use, and applies only its `Resize`; anyone else's is dropped without an answer. Until some Client has reported focus, and after that one leaves, any Client's resize applies. A GUI that reports focus measures every Panel again, since sizes it sent while another window sized the terminals were dropped. A rule kept entirely in the GUI, "only the active window sends sizes", was declined: with one GUI in the background, a Pane the CLI opens would stay 24×80 until the window came forward, and orchestration from the CLI is what ADR 0009 exists for. tmux's `window-size latest` is the same idea keyed on input.
- BEL attention no longer needs a controller to be raised. It waits for any Client to focus the Pane, and a Client leaving acknowledges nothing.

A window that does not size a Pane draws the Server's grid from its top-left corner, as a viewer did: the rest of the Panel keeps the background colour and what does not fit is cut off, until the person clicks into it.

The protocol loses `AcquireControl`, `ReleaseControl`, `ControlGranted`, `ControlReleased`, `ControlDenied` and `ControlDenialReason`; the GUI loses the "Viewing only" note in the Tab strip, its retry loop and every check of `controlling`, and `can_mutate` now means synchronized. The Settings page keeps its own "Viewing only" for admin commands over TCP and Peer-to-peer (ADR 0015), which is a different thing. Their field numbers are reserved, as CI's `buf breaking` requires, and `PROTOCOL_VERSION` stays 1: breaking changes are allowed before the first stable release, and the release notes already say to update the app and every Device together. A 0.1.8 GUI on a newer Server is never granted control and stays read-only; a newer GUI on a 0.1.8 Server receives a `ControlDenied` it cannot read, which ADR 0028 turns into "update this Device".

The stale connection itself is now found from the Server's side. A GUI's writer sends a `Ping` after `HEARTBEAT_INTERVAL` (10 s) without any other message, from the writer thread so a stalled UI thread cannot cost the connection, and the Server gives every connection that has sent `Subscribe` a 30 s read timeout, after which it drops it as if it had closed. The CLI never subscribes and is unaffected. A remote bridge whose `ssh` died ends within 30 s. The GUI's wake probe stays: it finds a dead connection from the Client's side.

This amends ADR 0003 (one active input and resize controller per Session), ADR 0004 (control grants committed only once queued, and re-acquired after a subscription rejection), ADR 0005 (control acquisition retried by a replacement connection and cleared on a new authority), ADR 0007 (a viewer without control), ADR 0008 (the selection belonged to the controller and was cleared when control changed hands; it is now every Client's and stays), ADR 0009 (the viewer state that stayed with the controller) and ADR 0020 (the "Viewing only" mode in the Tab strip and `control_denied`).

Tests: a stale `Focus(false)` leaving another Client's focus in place, and the holder's focus and sizing ending with its connection; a non-focused Client's resize dropped while the focused one holds the terminal and applied once it leaves, with the leaving Client's mouse button released before its focus; a bell waiting through a Client leaving; a GUI that becomes usable while another Client stays subscribed; reporting focus dropping stale pending sizes; and an unsynchronized Dock resize sending nothing.
