# Terminal Rendering Uses a Coalesced Visual Stream

Condr separates terminal presentation updates from reliable Session events. The Server remains the owner of PTYs, VT state, and terminal revisions; the GUI remains an event-driven presenter and does not poll terminal state on a display timer.

A reconnect Bootstrap contains complete terminal views. After subscription, layout, lifecycle, agent, and Git changes use the ordered reliable event stream and its replay cursor. Terminal pixels use independent `TerminalFrameBatch` messages that are neither assigned a Session sequence nor retained in event history. Each client has its own terminal baseline. The Server sends a full view without a baseline or after a resize, and otherwise sends changed cell runs plus viewport and cursor metadata.

Each client writer has a reliable queue capped at 512 items and enough bytes for the largest framed Bootstrap the protocol allows (its header frame, every batch envelope and length prefix, and the full aggregate record payload) plus one normal frame, along with one replaceable clipboard slot and one bounded visual slot. A fenced Bootstrap keeps an unsent clipboard copy in that slot, since clipboard state lives in neither the Bootstrap nor the event history; only lag recovery discards it. If a client exceeds the reliable bound, the backlog is replaced by one subscription rejection; the client requests a new authoritative Bootstrap and resubscribes instead of consuming memory without limit. A lagged writer is not a dead one: the connection stays open, direct responses dropped by the lag are not retried, and control grants or releases commit only when their response was actually queued, so the client never holds a belief the Server did not confirm. An overflow also discards responses that were queued but not yet written, so consistency rests on the client always re-acquiring after a rejection rather than on every response arriving. The GUI treats the Bootstrap that follows a subscription rejection as a recovery point in any subscription state: it re-acquires control and drops pending layout projections, whereas a Bootstrap requested for a visual revision gap leaves control state untouched. A visual batch may contain updates for multiple Panes. Reliable messages are always dequeued first. The Server advances a client's terminal baseline only when the corresponding visual batch enters the slot. If the slot is full, it retains only the affected Pane identities; after the writer drains, the Server regenerates a frame from the latest authoritative VT state against the last committed baseline. It does not enqueue or replay obsolete intermediate views.

The producer reads `alacritty_terminal` damage once per coalesced wakeup. Full damage produces a complete view; partial damage reads only the affected cell ranges and produces a semantic delta against the previous producer revision. The Server applies that delta to one retained view per Pane. Per-client baselines share retained snapshots, use the producer delta directly when its base revision matches, and fall back to a retained-view comparison only for a client that skipped frames. OSC 8 targets use a self-contained intern table in every full or delta wire frame. The Server reapplies the per-URI and cumulative hyperlink byte limits when a link-bearing delta changes its retained view, including any resulting link clears in the published frame. Bootstrap and render frames use the same projection before encoding, and a client's baseline advances from that actual projection rather than the unencoded authoritative view. Per-client fallback comparison and bincode serialization happen outside the Session state lock. Pane batches are sized before encoding and each accepted batch is serialized once.

A fresh Bootstrap clears any queued visual batch, clears deferred Pane identities, and resets the client baseline to the Bootstrap views. A visual batch already being written remains ordered before that Bootstrap on the transport. The GUI applies deltas only to their declared base revision and requests one fresh Bootstrap when a baseline is missing or a revision gap is detected. Selection and other presentation-only interaction remain local to the GUI. (Finished selections: superseded by ADR 0008.)

Condr intentionally adds a second coalescing boundary at the GUI event-loop ingress. Reliable messages remain FIFO, while at most one visual-ready token is queued. Cell-run deltas for each Pane are composed in the reader thread, so GPUI receives the latest applicable semantic frame instead of replaying every frame already read from the socket. Bootstrap advances a local generation and invalidates any older visual token, which prevents a coalesced pre-Bootstrap frame from being applied afterward.

The GUI applies every accepted terminal frame to its retained connection snapshot, but invalidates the GPUI root only when the frame intersects the Pane leaves mounted by the active Dock projection. Frames for another Server, an inactive cached Tab, or Panes hidden by zoom remain available for the next navigation without causing background layout, prepaint, resize, or paint work. Before the active Dock is first mounted, active-Server frames still wake the root so the initial terminal view cannot lose its presentation signal.

This follows the render ownership and backpressure semantics verified in herdr v0.8.2: its client transport has separate reliable and capacity-one render queues, while its render stream commits a baseline only after a render is accepted and regenerates deferred output after writer drain. Condr does not copy Herdr's TUI refresh mechanics. Herdr can apply a dequeued terminal render directly to a terminal surface; Condr crosses a GPUI task boundary and therefore needs the additional GUI ingress slot and Bootstrap generation barrier. Condr also uses `alacritty_terminal` damage and semantic cell-run frames because its GUI retains and selectively repaints terminal cells, whereas Herdr's TUI stack uses libghostty-vt and its own dirty-row/render encodings. The Server still owns the 60 Hz publication cadence; the GUI remains event-driven and does not poll on a display timer.
