# The Changes Sidebar Reviews a Workspace Through a Server-Owned Diff Pane

A right sidebar lists what has changed in the presented Workspace's working tree, and clicking a file shows that file's diff in a Tab. The point is reviewing what an agent did without leaving Condr; it is not a source-control client. Nothing in this decision stages, commits, discards or edits.

The Server computes everything with `gix`, as the Git rule in `AGENTS.md` requires, so the sidebar works the same against a remote Server; unlike "Open in", which spawns a program on the GUI's machine, a diff is data and travels over the protocol. "Changes" means the working tree against `HEAD`: index and worktree differences are not told apart, untracked files count as wholly added, and rename tracking is on so a moved file shows as one entry with both paths. The changed-file list, each entry with its status and added/deleted line counts, rides in the existing `WorkspaceGitChanged` event next to the branch and upstream, so a reconnecting client gets it with its bootstrap. Diff text is not pushed: the client asks for one file at a time and the Server answers with the hunks that `gix_diff::blob::UnifiedDiff` produces, already structured as lines with their kind and old/new line numbers, never as patch text to be parsed again. The request carries an `against` field that only accepts `HEAD` today; the branch-against-its-base view that agent worktrees will eventually want (a dirty tree would show uncommitted changes, a clean one the branch against its base) reuses the same messages. Caps keep a large repository from stalling the list: the status list stops at 1000 entries and says so, line counts are skipped once that cap is hit, a file over 1 MiB or binary yields a placeholder instead of hunks.

The Server refreshes the list from a filesystem watcher (`notify`) on the working tree, debounced, ignoring `.git` internals and ignored directories, in addition to the fingerprint scan that terminal activity already triggers. Agents mostly change files through the terminal, but editors and scripts do not.

The diff opens in a Pane, and a Pane so far has meant a terminal. A Pane gains a kind: `Terminal`, which is everything a Pane is today, or `Diff { path }`, which has no PTY and shows one file. Each Workspace has at most one Tab named "Diff": `LayoutCommand::ShowDiff { workspace_id, path }` creates it with a single Diff Pane the first time and afterwards retargets that Pane and activates the Tab, so clicking through the list never accumulates Tabs. The Diff Pane is Session state like every other Pane (ADR 0001) and is persisted in the snapshot (ADR 0005), so it survives reconnect and Server restart; it closes like any Tab. A GUI-only viewer tab was rejected because the Tab strip is a projection of the Session and a Tab that vanishes on reconnect would break that. Showing the whole changeset in one scrolling document was considered and declined for now: one file at a time is what was asked for, and the Pane state can grow a focus field later. `CONTEXT.md` widens the definition of Pane accordingly.

The sidebar follows the interaction and layout of Zed's git panel at its default settings, because that is the reference the user works with daily: sections Conflicts, Tracked and Untracked with collapsible muted headers; a flat list sorted by path; a row made of a status glyph (square-plus added, square-dot modified, square-minus deleted, warning for a conflict, each in the theme's version-control colour), the file name first and its directory dimmed and truncated from the start, and `+N −N` on the right; deleted rows struck through. The staging checkbox is left out. The header reads "Changes (N)". Zed is GPL, so only the design is borrowed; the rows are GPUI Kit components.

The diff is rendered with GPUI Kit's `Editor` in read-only mode: the hunks are laid out as unified-diff text, the `diff` tree-sitter grammar colours added, removed and hunk-header lines through the theme, line numbers are on, and a `TextDecorationCollection` tints added and removed lines. This buys selection, copy and search for nothing and costs three known limits: the tint covers text, not the full row; the gutter shows the patch's own line numbers rather than old and new; and there is no split view. If those start to matter, a custom element over GPUI's text primitives replaces the Editor while the Server, which already hands over structured lines, stays as it is. Syntax highlighting of the file content, word-level diffs, sticky headers across files, and Server-side highlight tokens on the wire are all later work, and none of them changes this decision.
