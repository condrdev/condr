# A Push Names the Device as the Phone Lists It

Status: accepted 2026-11-03. Amends ADR 0047, whose push body ends with the Server's `device_name` and whose Condr Cloud stores no name; builds on ADR 0040, whose Companion lists each Device by a name the person can change.

ADR 0047 ends a push's body with the Server's `device_name`, its host name, written into the text by the Server. The Companion lists a Device by the name the person gave it or, left alone, the one its Server reported at pairing (ADR 0040), and renaming it there never reached the push: a phone listing `rocky-mbp` as "Work Mac" still read "… · rocky-mbp" on its lock screen. The phone cannot rewrite that text: APNs shows `alert.body` as sent and the Companion has no Notification Service Extension (ADR 0047), and Android shows an FCM notification message itself while the app is in the background.

Condr Cloud already holds which Devices each phone takes pushes from, so it holds the phone's name for each as well and finishes each recipient's body. `PUT /api/push/device` takes `servers` as `[{id, name}]`, `name` optional: the name the phone lists that Device by, typed or reported, so a push names a Device as the app's list does. The phone registers again whenever a name changes, as it already does when a Device is added or removed; renaming happens in the foreground, so it takes effect at once for every Server, connected or not. `POST /api/push/send` carries the `body` without the Server's name, `detail · Workspace · terminal title`, still cut to 1 KB, and a new `serverName`, the Server's `device_name`. Condr Cloud sends each phone `body · name`, `name` being that phone's for the caller, else `serverName`, empty parts left out; the name is added after the cut, so the cut never removes it. D1's `device_server` gains a nullable `name` column.

A name, the phone's or `serverName`, that is neither absent nor a string is refused with `400`. One is trimmed, counts as absent when empty, and is cut to 64 bytes of UTF-8 at a character boundary rather than refused, since a refused registration would silence every push to that phone. The 4 KB payload check still runs before recipients are looked up, leaving room for a 64-byte name, so its answer never depends on what another phone registered. Sixty-four named Devices stay well inside the 16 KB request limit.

Condr Cloud therefore stores one thing more: the name each phone gives each of its Devices, often a person's name, as a host name is. It already saw the host name in every push. `SECURITY.md`, the privacy page and `CONTEXT.md`'s Condr Cloud entry say so with the implementation.

Accepted: a computer whose host name changes after pairing keeps its old name in pushes, as it does in the app's list, until it is renamed on the phone. The phone does not record whether a name was typed or reported, and sending only typed names would need that in both apps' storage.

The desktop notification names the Device too, from its own side: an Agent's change, a program's OSC 9 or 777 notification (ADR 0054) and a long command's end (ADR 0055) each end their body with the name the sidebar lists the Device by, once more than one Device is saved. With only this machine every notification would end in "Local". The count is of saved Devices, not connected ones, so the text does not change as one drops.

Not chosen:

- The Server substituting: the phone would tell each Server in `Hello` what it calls it, and the Server would keep that in `authorized-clients.json` and send one push per distinct name. It adds a protocol field, has the Server store the phone's naming, and a rename reaches a Server only when the phone next connects to it, while the registration the phone already sends reaches Condr Cloud at once.
- The phone substituting: a Notification Service Extension with `mutable-content` on iOS, and data-only FCM messages the Android app draws itself. It reverses ADR 0047's decision against an extension and adds a target and a second notification path for one word.
- Condr Cloud stripping the host name off the end of `body`: the 1 KB cut may have removed it, and any part may contain ` · `.
- Sending every part (`detail`, Workspace, terminal title) for Condr Cloud to join: only the name differs between recipients, and moving the join and the cut into the Worker changes no text while Condr Cloud would still have to take `body` from older Servers.

Condr Cloud's `API-Version` stays `1`, and each side's older release degrades rather than fails. A Companion from `companion-v0.2.0` sends `servers` as strings, which Condr Cloud reads as Devices without a name, marked `compat(companion-0.2.0)`. A Server from 0.2.0 sends its name inside `body` and no `serverName`, and Condr Cloud forwards that body unchanged, marked `compat(0.2.0)`: its pushes keep the host name until it updates. Condr Cloud ships first, with its migration; against the Condr Cloud before it, a newer Server's pushes would name no Device and a newer Companion's names would be ignored.

Tests: in Condr Cloud, a push names the Device by the recipient's name, falls back to `serverName`, and two phones with different names each get their own; strings in `servers` register Devices without a name; a body without `serverName` goes out unchanged; a name is trimmed, an empty one is absent, a long one is cut at a character boundary and a non-string is refused; the 4 KB check passes or fails the same whatever names the recipients registered. On the Server: the body no longer carries the name and `serverName` is its `device_name`. In both Companion apps: renaming a Device registers again with the new name. In the GUI: a notification ends with the Device's name with two Devices saved and without it with one.
