# Layout Changes Carry Their Snapshot

`SessionEvent::LayoutChanged` carries the new structural `SessionSnapshot` and the live zoom state. A client applies it in place: it replaces its structure, drops terminals of Panes that no longer exist, and settles whatever was waiting for that sequence. It does not request a Bootstrap.

Before this, the event was a bare signal and every structural change made the GUI fetch a full Bootstrap: the structure plus every terminal's whole screen, agents and Git state. While that round trip was in flight the client counted as unsynchronized, so every control rendered disabled, and on arrival all terminal views were replaced. Switching a Tab therefore dimmed the whole window and repainted every Pane. The structural Snapshot is a few kilobytes, and the event history already replays it to a resubscribing client, so carrying it costs nothing the protocol did not already pay.

Consequences: the GUI requests Bootstrap on initial connection, reconnect, a rejected subscription or a reliable/visual revision gap. Derived per-Workspace state that used to ride along with the Bootstrap after a layout change must be published as its own event; Git detection therefore raises `WorkspaceGitChanged` whenever a layout operation records a repository. A Pane the structure announces before its terminal has been seen is filled in by that terminal's first full frame, which `apply_terminal_frame_batch` accepts for an unknown Pane. Titles are separate lifecycle metadata: reliable title events are retained before the first visual frame, survive that frame and are pruned when the Pane closes. The origin client receives the event before its `LayoutApplied`; a `LayoutApplied` that arrives after its event settles pending projections immediately instead of waiting for a Bootstrap that no longer comes.
