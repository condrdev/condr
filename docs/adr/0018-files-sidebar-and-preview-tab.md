# The Right Sidebar Gains a Files View and a Server-Owned Preview Tab

The right sidebar that ADR 0017 introduced for Changes now has two views, chosen by two tabs in its header, Files first: Changes stays as decided there, and Files shows the presented Workspace's directory tree. Clicking a file opens its content in a Tab. The point is reading what an agent touched, or the file next to it, without leaving Condr; like Changes it edits nothing, and it is not a project explorer: no create, rename, delete, stage or commit. Of the agent-orchestration GUIs surveyed (Superset, Paseo, Orca), every one couples the tree to file editing and Git writes; Condr keeps the boundary ADR 0017 drew, because the conversation and tool loop belong to the agent CLI.

The header is a tab strip in GPUI Kit's default tab style, tabs sized to their labels, the Changes tab carrying its count. The summed `+N −N` of the working tree sits at the strip's far end whichever view is shown, so switching to Files never hides how much has changed. Which view is shown is Client state per Workspace and is not persisted: a Workspace inside a repository opens on Changes, one outside opens on Files, since its Changes view can only say it is not a repository; a tab the user picks is kept for that Workspace until the GUI closes.

The tree is Server data like everything else in the sidebar, so it works the same against a remote Server. Listings are plain filesystem reads under the Workspace's Root Directory, one level per request (`ListDirectory`), because browsing a Workspace does not require it to be a repository; `.git` is left out, dotfiles are shown (agents edit `.github/` and `.claude/` often), directories sort before files, both by name ignoring case, and a level stops at 2000 entries and says so. When the Workspace is inside a repository, the Server flags each entry the ignore rules exclude, using the same `gix` exclude stack the watcher already consults, and the GUI dims those names; they stay listed and unfold like any directory, since a lazy listing makes an ignored `target/` cost one row. There is no toggle to hide them. A directory whose subtree holds a change carries a small dot, and a changed file shows its Changes status glyph, so a folded tree still says where the agent worked. Nothing is pushed: the client asks for the root when the view is shown and for a directory when the user unfolds it, and folding a directory drops its listings so unfolding reads afresh.

Refresh rides the watcher the Server already runs on every Workspace root. Each debounced batch now also publishes `WorkspaceFilesChanged { workspace_id }`, repository or not; it names no paths, and a client answers it by asking again for every listing and file it holds for that Workspace, keeping the old answer on screen until the new one lands. A batch that touches only ignored paths is not reported, exactly as it does not trigger a Git recomputation, so a `cargo build` churning `target/` refreshes nothing. Paths in the event, with per-directory invalidation as Superset and Orca do, were declined: only unfolded directories are cached, so re-listing them all is cheap, and carrying paths means handling overflow and renames at both ends.

The file opens in the Workspace's single Preview Tab, `TabContent::File { path }`, the second viewer kind ADR 0017 reserved: no Panes, at most one per Workspace, identified by its content and not by its display name "Preview", created by `LayoutCommand::ShowFile` the first time and retargeted and activated afterwards, persisted in the snapshot, closed like any Tab. It sits beside the Diff Tab rather than sharing it, so a diff and a file can stay open together and clicking through either list never disturbs the other. Content comes from `ReadFile`: the same 1 MiB cap as a diff, a NUL byte in the first 8000 bytes means binary, and text is decoded lossily so a stray invalid byte does not blank the view. Images and other binaries show a placeholder. The Tab renders it in GPUI Kit's read-only `Editor` with line numbers, search and copy, highlighted by the grammar the file's extension names. Condr compiles every grammar GPUI Kit ships except SQL, whose crate pins a `cc` older than the Windows resource embedding needs; the set costs about a minute and a half of extra build time and roughly 36 MiB of debug binary. The Diff Tab keeps its `diff` grammar: highlighting hunks by the file's language needs either Server-side tokens on the wire (Paseo) or a different viewer (Orca's Monaco), both out of scope here and noted in ADR 0017 as the point where the Editor gets replaced.

Rows carry file-type icons from Material Icon Theme (MIT), the set VS Code users know and Superset ships: 822 SVGs, about 640 KiB, with the theme's own name and extension tables regenerated by `script/generate-file-icons.mjs` and looked up as VS Code does, exact file name first, then the longest dotted suffix (`app.test.ts` before `ts`), directories by name. The icons are multi-colour, so they are drawn with `img()`, which rasterizes an SVG as it is, rather than `Icon`, which tints a silhouette; a monochrome Lucide subset was considered and dropped for telling too few types apart, and Nerd Fonts glyphs for needing a bundled font and a hand-kept mapping while covering fewer file types (about 800 of its 11,000 glyphs) at four times the size. Light-theme variants and folder "open" variants are left out: the dark icons read in both modes and the chevron already says a directory is unfolded. The set is drawn for VS Code's brighter chrome and glared on Condr's dark panels, so the theme's own saturation setting is applied as a `feColorMatrix saturate` filter baked into each SVG by the script (0.75). The theme's other dial, opacity, was tried at draw time and dropped: it made the icons look washed out rather than quieter. Ignored entries alone draw at half opacity. In the Files view the type icon keeps the slot and a changed file shows in the name's status colour; the Changes view keeps its status glyphs, and the Preview Tab header shows both.

A file row in either view has a context menu with the read-only actions a path affords: Copy Relative Path, Copy Path, Open in the Workspace's "Open in" editor (local Servers only, for the same reason as the title-bar button), and Insert Path into Terminal. The last is Condr's own version of Paseo's "Add to Chat": it pastes the relative path, quoted when a shell would split it and followed by a space, into the Workspace's last presented terminal Tab (the first terminal Tab until one has been presented) and activates that Tab, because clicking a file has just made the Preview Tab active and the terminal the user was talking to is no longer on screen. It is disabled when the Workspace has no terminal Tab. The path is not prefixed with an agent's reference syntax such as `@`, since Condr does not distinguish agents here.

Declined for now, each a separate decision when friction shows: comparing the branch against its base (all three surveyed tools have it; the `against` field ADR 0017 reserved is where it goes), a name filter over the tree, keyboard navigation of the tree (none of the three have it), rendered Markdown, and persisting the view choice or the unfolded directories.
