# The Diff Tab Shows Changes Side by Side and the Right Sidebar Gains History

Status: proposed 2026-10-21. Supersedes ADR 0017's rendering paragraph (the read-only `Editor`, its three known limits and its three lines of context) and ADR 0032's sentences on the Diff Tab, which keep only the Preview Tab and Markdown. Amends ADR 0018, whose sidebar gains a third view and a refresh button, and ADR 0034, whose per-Client comparison gains a commit.

ADR 0017 named the point where the Diff Tab's `Editor` would be replaced: a split view, old and new line numbers, tints across the whole row. GPUI Kit 0.8 ships that viewer as `gpui_kit::component::diff`, which its `tig` example drives, so Condr takes it instead of writing its own. The same example shows a commit list beside the diff, and reviewing what an agent committed, not only what it left uncommitted, is the question ADR 0034 started to answer. So the right sidebar gains History, and the Diff Tab can show one file of one commit. Condr still is not a source-control client: nothing here checks out, reverts, cherry-picks, stages or commits.

## The Diff Tab

The Diff Tab renders with Kit's `Diff`. Condr declares `gpui-kit = "0.8"`, without its `syntect` feature (below); 0.8 compiled against Condr unchanged, and its behaviour changes (scroll bounce on macOS, nested scroll areas no longer chaining, a closed Dock tab handing focus to its replacement, the Markdown typography) are checked by hand on macOS and Windows with the upgrade. The wire stays as ADR 0017 has it: the Server sends structured hunks, never patch text. `DiffFile` has no public constructor from hunks, only `DiffFile::parse`, so the GUI writes the hunks out as a patch (`---`/`+++` with `/dev/null` for an added or deleted side, `@@` headers and prefixed lines) and parses that; a constructor upstream would remove the round trip. The patch names the file by a fixed placeholder rather than its path: Kit's own file header is hidden, since the Tab header already shows the path, the status and the counts, and the parser then never meets a path that needs quoting. Binary, too large, unchanged and failed keep Condr's own placeholders.

Split is the default, Unified the alternative, switched by a segmented control in the Tab header like the Preview Tab's Preview and Source. The choice is one for the whole GUI, not per Workspace: it is how this person reads diffs, not a property of a file. It is remembered in the GUI state file (ADR 0023) and never enters the Session. Line numbers are on and show old and new, and word-level emphasis is on. Split wraps long lines and Unified scrolls sideways: Kit sizes each Split column to the longest line, so without wrapping the new side would sit out of view. The Diff draws with Kit's mono font, which Condr already sets to the terminal's family and size, so ADR 0032's Code font size no longer reaches it, and on the GUI's background rather than the code theme's. None of these is a setting, and Kit's other options (character emphasis, context length, hunk separators) are left at their defaults.

`GitDiff` gains an optional `full_context`. When it is set the Server returns each file as one hunk holding every line, and Kit folds unchanged runs longer than its three lines of context into rows that expand up, down or entirely. With three lines on the wire, as before, a fold could only say how many lines it hides. The 1 MiB limits of ADR 0017 apply to the hunks returned; when the whole file passes them, the Server falls back to three lines of context, so no diff that showed before becomes too large. An older GUI never sets the field and keeps three lines.

`DiffState::set_files` resets scrolling, expansion and selection. The Diff Tab refetches whenever the working tree moves (ADR 0017), so while an agent edits the shown file it would jump to the top on every batch. A refetch whose patch text is unchanged therefore leaves the state alone; an agent editing another file no longer moves this one. A changed one is applied and scrolled back to the line last clicked. Kit does not say which line is at the top, so without a click the view returns to the top, and folds expanded by hand collapse again; both are accepted until Kit can keep the viewport across `set_files`.

Kit's `Diff` has no search, where the `Editor` searched with `secondary-f`. The loss is accepted: a Diff Tab shows one file, and Show File opens it in the Preview Tab, which searches. Show File now takes the new-side line of the line last clicked (a removed line stands for the line it was removed before, as ADR 0017 has it), or with none the first changed line.

The file content is not yet highlighted by its language, as it is not today. Kit's `Diff` highlights only through Kit's own highlighter, which needs its `tree-sitter` or `syntect` feature, and an application cannot hand it another. Turning on `syntect` was declined: it brings a second engine beside ADR 0032's, two-face 0.4.5 with fancy-regex syntaxes next to Condr's 0.5.2 (about 1 MB of binary and a second syntax set in memory), and it colours from Kit's roughly 35 highlight names, into which the chosen Highlight theme could only be approximated, losing its finer scope rules and its backgrounds. Replacing ADR 0032's highlighter with Kit's everywhere was declined too: Kit parses a document up to 64 KiB on the UI thread at every update, blanks a larger one until its reparse lands, and gives up Oniguruma and the newer syntaxes, which undoes what ADR 0032 built for a file an agent keeps editing. Instead Condr proposes upstream that `DiffState` accept an application highlighter, a function from a language and a hunk's text to styled ranges, run on the background thread where Kit already prepares each file, as `TextViewDefaults::with_code_block_highlighter` already lets an application highlight Markdown code blocks. Once a Kit release has it, the Diff Tab passes ADR 0032's highlighter, names the language with `with_language` since its patches carry no real path, and its colours match the Preview Tab's exactly. Until then, added and removed lines carry Kit's tints, from the GUI theme, and its word-level emphasis.

## History

History is the right sidebar's third view, after Files and Changes. It lists the commits reachable from the presented Workspace's `HEAD`, newest commit time first, as `git log` does without a graph; merged branches' commits are interleaved and not drawn apart. Each row has two lines: the subject, then the short id, the author and the age. A commit unfolds like a directory into the files it changed, against its first parent or, for a root commit, against nothing, with rename tracking and the status glyphs and `+N −N` of a Changes row. Clicking a file shows it in the Workspace's Diff Tab. A commit row's context menu has Copy Commit ID. Nothing else in History acts on anything.

Three Client requests serve it, each with a reply that carries its `request_id`:

- `GitLog { workspace_id, from, skip, limit }` returns up to `limit` commits after skipping `skip`, walking from `from`, or from `HEAD` when `from` is absent, together with the commit it started from and whether more exist. The GUI asks for 100 and asks again from the same commit with a larger `skip` when the list is scrolled to its end, so later pages stay consistent while `HEAD` moves. Each page walks again from the start; this is cheap into the tens of thousands of commits, and a cursor kept on the Server waits for a repository where it is not.
- `GitCommit { workspace_id, commit }` returns the full message, the author and time, the parents, and the changed files under ADR 0017's 1000-entry cap with its truncation flag. The GUI asks when a commit is unfolded.
- `GitDiff` gains an optional `commit`. When it is set, `against` is ignored and the Server diffs the path between that commit and its first parent, taking a renamed file's old path from that commit's own changes.

All three, and `GitDiff` as a whole, now run off the Client's request loop, as `BrowseDirectory` and ADR 0045's mutations do: walking a long history or diffing a thousand files must not stall terminal input.

Which commit the Diff Tab shows is the Client's view, as ADR 0034 made the comparison. The Diff Tab's Session content stays `Diff { path }`; a click in History sends the ordinary `ShowDiff` and puts the commit into this Client's own `GitDiff` requests, so another Client on the same Diff Tab may show the same path in the working tree. The commit lasts until the Diff Tab's path changes by anything but this Client's next click in History; a click in Changes, or another Client retargeting the Tab, returns it to the working tree. It is not remembered across runs. With a commit, the header shows the subject, short id, author and age, a Copy Commit ID button, and a disclosure with the rest of the message as selectable plain text, not Markdown. Show File then opens the file as it is in the working tree, at its top, since the commit's line numbers say nothing about today's file, and is disabled when the file no longer exists. A commit diff never refetches, because a commit does not change.

`WorkspaceGitChanged` gains `head`: a message present in every Git snapshot from a Server with this decision, holding the commit `HEAD` points at, or nothing when `HEAD` is unborn, in which case History says there are no commits yet. A new commit, a checkout or a reset changes it, publishes the event through ADR 0017's one function, and makes a GUI that has History loaded ask for its first page again. A Workspace outside a repository says "Not a git repository" in History as in Changes.

## Refresh

The sidebar header gains a refresh button beside the summed `+N −N`, shown in all three views and acting on the whole Workspace. It sends `RefreshWorkspace { workspace_id }`, which asks the Server's watcher for the forced scan that ADR 0045's mutations already trigger; that scan publishes `WorkspaceFilesChanged` whether or not the tree moved, and `WorkspaceGitChanged` when something did. The GUI also asks again for an open working-tree Diff and for History's first page. The button exists for when the watcher missed something: a filesystem without events, a network mount, a watcher that could not start. Only the Server can look again, so a refresh that only refetched in the GUI was declined. The icon spins until this Workspace's next `WorkspaceFilesChanged` or for at most five seconds, which covers a scan that fails and an older Server; no reply message was added for it. There is no keyboard shortcut.

## Compatibility

History is gated on `head`, as ADR 0034 gated the base view on `base`: a Server older than this never sends it, so the GUI does not show History for that Device's repository Workspaces, never sends `GitLog` or `GitCommit` to it, and so never sends `commit` in a `GitDiff` it would ignore. `RefreshWorkspace` has no such gate; before the first stable release the protocol stays at 1 (ADR 0041), so an older Server answers it with its "does not support that request; update it" error, shown with `report_error`, as ADR 0045 accepted for its requests. An older GUI ignores `head` and never sends the new requests or fields.

## Not in this decision

A commit graph; branches, tags or remotes other than `HEAD`'s history; a file's own history; a whole commit or the whole working tree as one scrolling document, which ADR 0017 declined and which Kit could now draw; search inside the Diff Tab; any commit action beyond copying its id; the Companion and the `condr` CLI. `CONTEXT.md`'s Diff Tab, Changes and Files entries, a new History entry, `AGENTS.md`'s dependency rule and the website change with the implementation, not before.

Tests, in core and the Server: `GitLog` orders by commit time, pages from a fixed `from` while `HEAD` moves, and reports no more past the end; an unborn `HEAD` sends `head` without a commit and an empty log; `GitCommit` diffs a root commit as all added, a merge against its first parent, a rename with both paths, and truncates past 1000 files; `GitDiff` with `commit` diffs a renamed file against its old path, and with `full_context` returns one hunk holding every line while without it keeps three lines; a commit changes `head` and publishes `WorkspaceGitChanged`; `RefreshWorkspace` publishes `WorkspaceFilesChanged` for a Workspace inside a repository and one outside; a slow `GitLog` does not hold up terminal input. In the GUI: hunks written as a patch parse back for an added, deleted, renamed and modified file; the Split or Unified choice survives a restart; a refetch with unchanged hunks keeps the scroll position and a changed one keeps the top line; History is hidden when `head` is absent and reloads its first page when `head` changes; a commit choice returns to the working tree when another Client retargets the Diff Tab; the refresh icon stops on `WorkspaceFilesChanged` and after five seconds without it; and visual tests of the split Diff Tab and of History.
