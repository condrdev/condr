# The Server's Terminals Run on libghostty-vt

Status: accepted 2026-10-28. Revised 2026-10-29: the pin starts at Ghostty 1.4.0, macOS 13 is the floor, recorded streams become fixtures, and the crate lands ahead of the switch. Replaces the `alacritty_terminal` choice in AGENTS.md. Amends ADR 0004 (where the producer's damage comes from), ADR 0008 (a selection survives resize and erase) and ADR 0044 (the VT reads OSC 7501 and 777 itself). Makes one exception to ADR 0028 for the cell columns.

The VT every Pane runs on the Server becomes libghostty-vt, Ghostty's terminal core behind its C API; `alacritty_terminal` and `vte` leave the workspace with no fallback engine. alacritty_terminal was chosen for being pure Rust with no FFI, and that is what this gives up, for three things it does not have. The first is protocol coverage. It has grapheme clusters and mode 2027, encoders for kitty and legacy keys, mouse, focus and paste, modifyOtherKeys, in-band resize reports, colour scheme reports, OSC 133 prompt marks, and OSC 7501 parsed by the implementation of the specification's own author. Condr had written about 900 lines of encoding and OSC scanning because alacritty_terminal has none of it. The second is memory: scrollback is paged, capped in bytes, compressible while idle and measurable per terminal. The third is accuracy, with esctest run in its CI. JetBrains IDEs made it their default terminal emulator in 2026.3, Paneflow runs on it on every platform, and herdr embeds it. libghostty has no versioned release of its own yet, and Ghostty plans one last ABI break before 1.0, so Condr pins a Ghostty commit, starting from the 1.4.0 tag, and moves it on purpose.

What it takes over, and what stays Condr's. libghostty-vt parses the stream, answers queries, encodes input, tracks the selection and exports text; `OscScanner` and Condr's OSC 7501 parser are deleted. The PTY write queue, the routing of mouse events between the application, the scrollback and alternate scroll, the cwd and Agent probes, the ConPTY cursor settling, the frame protocol, the per-Client baselines of ADR 0004 and URL detection stay; the library's search matches substrings, not the regular expression links are found with. The producer reads the library's render state, which marks dirty rows where alacritty marked column ranges and has one consumer, so the Server compares each dirty row with its retained view cell by cell before it emits runs, and a selection change, which rebuilds the whole render state, still leaves the Server as a metadata delta. libghostty-vt does not buffer a synchronized update (mode 2026) in its parser the way vte did, so the Server holds the frame while the program draws and ends a hold that lasts a second itself. That also fixes a fault of the old engine: Condr never ended vte's buffering, so a program that died between `?2026h` and `?2026l` froze its Pane until 2 MiB of output arrived.

The bindings are Condr's own, in a new crate, `condr-ghostty-vt`, which `condr-core` depends on only under its `runtime` feature, so the Companion never links it. `script/update-libghostty-vt.sh <commit>` runs bindgen over the official headers of that commit, allowing only the functions and types Condr calls and leaving out doc comments so a different libclang does not change the output, and the result is committed with bindgen's layout tests. Over it sits a thin safe layer for exactly what Condr uses: the terminal and its callbacks, the render state's rows and cells, the encoders, the selection, the formatter, compression and memory accounting. Every `unsafe` in the change lives in this crate, including one `Send` assertion for the terminal and its render state: the library asks only that calls on a terminal be serialized, and Ghostty itself shares one locked terminal between its IO and render threads, so the terminal stays in the `Arc<Mutex<…>>` it lives in today rather than moving to a thread per Pane. Three sources were declined. libghostty-rs, the bindings most Rust projects use, follows Ghostty at its own pace: its crates.io release pins a Ghostty commit from 2026-07-11, some 1870 commits behind Ghostty 1.4.0, and its master trails main by weeks, so every API Condr needs would wait on another project's upgrade. Vendoring its two crates, as a Zed fork does, starts faster but makes Condr the maintainer of several thousand lines it does not call. gpui-cn's published `ghostty-vt` is a third party with one maintainer. libghostty-rs (MIT) and herdr (Apache-2.0) may be read and borrowed from; Paneflow is GPL-3.0 and lends only its approach.

The crate's `build.rs` compiles libghostty-vt from source with Zig, as herdr and most Rust projects that embed it do. Prebuilt archives, which Paneflow and a Zed fork download instead, were weighed and deferred. They spare every machine Zig and one compile, but they need a workflow that builds four targets on native runners (upstream cannot cross-compile Windows MSVC), releases that are never deleted so old commits still build, and a manifest of their hashes. The compile they save is small: a Zed fork measured under a minute with a cold cache, about 600 MB of memory at its peak and some 650 MB of Zig cache, once per Cargo profile and target, after which Cargo does not run the build script again until the pin moves. A manifest in the crate records the Ghostty commit, the SHA-256 of the lib-vt source tarball upstream publishes and signs for each commit that passes its tests, the Zig version, and the SHA-256 of the headers the bindings were generated from. `build.rs` downloads that tarball, verifies it, keeps it outside `target`, checks that `zig version` is the one recorded, and builds ReleaseFast for the baseline CPU whatever the Cargo profile: the Zed fork measured Debug libghostty-vt's `vt_write` at about 3000 times slower once the scrollback is not empty, and AGENTS.md requires a usable frame rate from a debug build. Zig fetches its own packages on a first build. Ghostty builds lib-vt for macOS 13 and later whatever target it is given, so that becomes Condr's floor on macOS, and `.cargo/config.toml` sets `MACOSX_DEPLOYMENT_TARGET` to match. `build.rs` refuses headers other than those the bindings came from, so a pin moved without regenerating the bindings does not build. `CONDR_GHOSTTY_VT_SOURCE_DIR` points it at a local Ghostty checkout, to try an upgrade or debug the library; `CONDR_GHOSTTY_VT_SKIP_NATIVE` makes it compile and link nothing, which is how the Mac runs Clippy for Windows and Linux without a Windows SDK. Zig, at the exact minor version Ghostty requires (0.15, 0.16 and 0.17 in turn within 2026), is installed with mise on the development machines and with setup-zig in CI, where its caches are kept between runs, since rust-cache does not keep a workspace member's build output. Ghostty moves only when Condr needs a fix or an API, only to a commit upstream published a source tarball for, and the manifest, the bindings and the safe layer's changes land in one commit. The license notices gain what the static library carries beyond the Rust crates cargo-about sees: Ghostty, simdutf, Highway, uucode, Wuffs and Zig's compiler_rt.

Agent state keeps its sources and loses its scanner. libghostty-vt parses OSC 7501 and OSC 777 and hands them to the Server through callbacks, so nothing has to be cut out of the bytes ahead of the VT any more. It answers `OSC 7501 ; ?` itself, in stream order, so the answer still precedes the DA1 reply as ADR 0044 requires; the answer lists the states and kinds it accepts (`?:states=…:kinds=…`) with the request's terminator instead of a bare `?`, and a report that repeats `state` takes the last one instead of being dropped. The library is the specification author's implementation, so where they differ Condr follows it. It reads OSC 777 into a 2 KiB buffer, half of what the scanner allowed, so `condr agent-hook` caps one event below that. Prompt marks arrive for every prompt kind, and only a primary prompt ends a `working` record. The DA1 and size callbacks are mandatory: the library answers neither without them, and Claude Code and Pi read the DA1 reply as the end of their OSC 7501 probe.

Keys are encoded by libghostty-vt from the terminal's live modes. Condr keeps three overrides, each for a fault it once fixed: Shift+Enter sends LF in legacy mode, Cmd produces no text on any Server platform (the library suppresses it only when built for macOS, so a Linux Server reached from a Mac would type it), and Cmd+C goes out in kitty form to a program that reads kitty keys without having asked. Ctrl+Enter, Ctrl+Tab and Shift+Esc become xterm's `CSI 27;…~` forms instead of the bare CR, tab and ESC they sent. The protocol's keys carry text and named keys, not physical keys, so the Server derives a physical key from a US layout until the protocol carries one.

The selection is libghostty-vt's. It follows output and reflow as ADR 0008 asks and is cleared on a screen swap, but it is no longer cleared on resize or when an erase touches it, and a double click on a bracket selects a word, not the bracketed span. A resize is what switching windows does under ADR 0036, and losing the selection to it was the worse behaviour. The Server converts the Client's half-cell sides to the library's inclusive cells.

The terminal says what it is. `TERM` stays `xterm-256color`, XTVERSION answers `Condr <version>`, XTGETTCAP's name query answers `xterm-256color`, and DA1 declares what the library implements; it otherwise introduces itself as libghostty and answers from Ghostty's terminfo, which describes a different terminal. No `TERM_PROGRAM` is set. Kitty graphics, the Glyph Protocol, DECRQCRA checksums and title reports stay off, and no clipboard read callback is installed, so ADR 0007's copy-only clipboard holds. On Windows a resize does not pull scrollback back onto the screen, which keeps the VT's screen and ConPTY's in agreement. The library's log goes to `tracing` (ADR 0019). CSI 22 and 23 t, the title stack, are lost: libghostty-vt does not implement them.

Each Pane keeps 50 MB of scrollback in the library's logical bytes, with no line limit, and compresses it while idle; these are Ghostty's defaults. libghostty-vt runs no timer, so the Pane's monitor thread starts the compression once the library's activity token has stopped changing. Ghostty measures text-heavy history at 10 to 30 percent of its uncompressed size once compressed. Today a Pane keeps 10,000 lines of 24-byte cells, about 48 MB at 200 columns, none of it compressed. Neither the limit nor the memory a Pane uses is a setting or shown yet. Grapheme widths follow Unicode by default, with mode 2027 set as the reset default, as Ghostty does. The Agent CLIs measure graphemes (Ink through `string-width`, ratatui by cluster); a shell that measures with `wcswidth` can misplace its cursor after a complex emoji in its prompt. The iOS Companion feeds the cells to SwiftTerm, which measures widths again, so a ZWJ sequence can misalign there until the app draws the grid itself, as Android does under ADR 0048.

The cells on the wire are redesigned on libghostty-vt's style model instead of alacritty's bits. A cell's `flags` become a `u32`: its width in two bits (narrow, wide, a wide character's spacer, or the spacer that ends a line before one), its underline style in three (none, single, double, curly, dotted, dashed), then bold, italic, faint, blink, inverse, invisible, strikethrough, overline and the detected-link mark. Foreground, background and a new underline colour column each hold default, a palette index or RGB. Alacritty's named colour numbers go; a Client dims a faint cell itself, and the palette stays the Client's. `PROTOCOL_VERSION` does not move. That breaks ADR 0028's rule that fields are only added: a peer from before reads the new columns wrongly instead of being refused, and the build warning of ADR 0027 is all it sees. This was accepted because few installs exist yet; it ships as 0.2.0, and the Companion moves to 0.2.0 with it, so the version alone tells which desktop and phone go together.

Left for later, each with its trigger: prebuilt archives per target, once the integration has settled, or sooner if Zig's version churn or the compile starts to cost on a development machine or in CI; colour scheme reports (CSI ? 996 n and mode 2031) with the palette reported to the Server so OSC 11 answers with the Client's background, first among the features; OSC 133 prompt navigation and selecting a command's output, with shell integration; scrollback search; OSC 9 and 777 notifications, OSC 9;4 progress and OSC 7501's progress; scroll deltas by row id, when remote bandwidth is measured; physical keys in the protocol for full kitty keyboard reports, when a layout bug asks for them; a scrollback setting and per-Pane memory in the CLI and Settings, when someone asks; the iOS app drawing its own grid; kitty graphics and terminal content kept across a Server restart, each with an ADR of its own, the second amending ADR 0005.

Tests: the existing terminal tests, ported to libghostty-vt, are the regression baseline. Before alacritty_terminal leaves, recorded PTY streams of Claude Code, Codex, OpenCode and vim, a few hundred KB in all, are replayed through both engines; every difference in the text grid and the cursor is reviewed, and the accepted grids stay as fixtures each later move of the Ghostty pin must pass. Fuzzing and ThreadSanitizer were declined: upstream fuzzes libghostty in its own CI, and Ghostty itself shares one locked terminal between threads. The performance acceptance of AGENTS.md runs again: burst wakeups coalescing to the latest revision, the final frame never dropped, unchanged cells not reshaped, a real GPUI drag-selection, and on Windows an observation of interaction and frame rate under an Agent's animation. Claude Code, Codex and OpenCode are run on macOS, Linux and Windows, legacy and kitty keys alike, for the overrides above, the OSC 7501 answer arriving before the DA1 reply, and the identity answers. RSS is compared before and after under one scripted workload of several Panes streaming output. Unit tests cover `build.rs` refusing a wrong tarball hash, a wrong Zig version and mismatched headers, `condr agent-hook` staying under 2 KiB, a synchronized update ended after its timeout, a selection kept across a resize, and the new cell columns round-tripping.

Delivery: `condr-ghostty-vt` and its build land on `main` first, built and tested on their own, so a Zig or toolchain fault on a development machine or CI runner surfaces apart from the migration. The switch itself lands in one merge, once Condr has been used on it day to day and the Windows acceptance above has passed.
