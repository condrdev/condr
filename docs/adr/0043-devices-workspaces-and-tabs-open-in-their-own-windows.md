# Devices, Workspaces and Tabs Open in Their Own Windows

Status: proposed 2026-10-14, planning only. Revised 2026-10-28 against ADR 0045 and ADR 0046: the right sidebar stays with its Workspace, a click that retargets a viewer Tab activates no window, detached windows gain Bring back, and the left sidebar lists only the window's scope. Nothing here is built, and nothing here is final: the design is still under discussion, and any part of it may change or be broken before it is accepted. When accepted, it amends ADR 0020 (a third kind of page in the content area), ADR 0021 (a View also says which window shows what), ADR 0023 (the state file gains a list of windows), ADR 0036 and ADR 0041 (one Client with several windows).

A person developing with two screens has one Condr window, and every mainstream tool is a single-window application. A Device, a Workspace or a Tab can be opened in a window of its own, moved to the other screen, and brought back. This is the GUI's own affair: the protocol, the Server, the Session and the Companion do not change, and the `condr` CLI gains no surface.

## Windows

The GUI process has one main window and any number of detached windows, all in the one process, opened with `open_window` as Settings is (ADR 0038); the single-instance lock stands. A second GUI process was declined: it would be another Client to every Server, with its own subscription of every Pane's frames and its own claim on the terminals' size (ADR 0036), and it could share neither theme, update check nor state file with the first.

A window shows one scope of the Session tree: everything, which is the main window; one Device; one Workspace; or one Tab. A Tab window holds exactly one Tab and draws neither Tab strip nor sidebars; a Workspace window has the left sidebar listing only that Workspace, collapsible, and the right sidebar with Changes, Files and History exactly as the main window has it; a Device window is the main window's chrome filtered to one Device. The scope filters everything the left sidebar lists, the "Needs you" list included, so a detached window lists only what it shows; the main window, whose scope is everything, keeps listing what other windows show, and a click on such a row is navigation (below). The OS title and the drawn title bar read `Condr – <name>`. One window view type carries the scope as a field, so every action handler and keybinding the main window has, a detached window has too. A Pane is not a unit of its own in this version, and a Tab window cannot hold more than one Tab; both wait, below.

Detaching moves, it does not mirror. A Tab, Workspace or Device is drawn in exactly one window at a time, so a `TerminalPanel`, its focus handle and its IME composition belong to one window, and ADR 0036's single terminal size has no second window of the same Client to fight. The place it left keeps listing it, in the sidebar or the Tab strip, and selecting it there shows a page in the content area, in the family of ADR 0020's connection pages: it says the item is shown in another window and offers to go to that window or to bring it back. The right sidebar belongs to the Workspace, not to the Tab: while only a Tab is elsewhere it stays, so a Diff Tab moved to the other screen is still driven from this window's Changes and History, and it leaves only with its Workspace or Device. The moment something is detached, its home keeps it selected and shows that page at once, so the person sees where it went; this is one rule for every unit, rather than a browser's habit of selecting the neighbouring Tab.

Bringing back is closing the detached window, or its title bar's Bring back button, which does the same so that bringing back does not hide behind the close button. `cmd-w` stays `ClosePane` in every window, as in the main window: in a Tab window with one Pane it ends that Pane's program, so it is never the way back. Closing a detached window asks nothing about unsaved Preview text (ADR 0045), since the Tab comes back with its text; closing the main window still asks about the unsaved text in every window, as it does today. A unit brought back returns to the nearest ancestor that has a window: a Tab to its Workspace's window if one is open, else its Device's window, else the main window, and it becomes the shown item there. A Workspace may be detached from a Device window, and returns to it while it is open. A Tab window outlives its Workspace being detached or brought back, and a Workspace window closing brings back the Workspace and leaves the Tab windows alone. A Tab moved to another Workspace by `MoveTab` keeps its window, whose scope follows the move. A window closes itself and drops its state entry when its Tab closes, its Workspace closes, its Device is removed under Settings, or a Bootstrap no longer has its id; a Device that merely disconnects keeps its windows, which show ADR 0020's connection state. Closing the main window quits and takes every window with it, as it takes Settings today.

A new window opened from the menu appears on the display the menu was on, at the main window's size, cascaded from it, with no minimum size, as the main window has none; one opened by dragging appears with its top-left corner at the cursor. After a restart the main window opens first, then the detached windows, and the main window is activated last. Stacking order is not remembered.

## One Client, several windows

A GUI process stays one Client per Server, so the Server still has one holder of the terminals' size (ADR 0036, ADR 0041), and a `Resize` from any of this Client's windows applies while it holds the sizing. The focus the Client reports follows the window last activated: "the window is active" means any of this Client's windows is, the focused Pane is the one focused in that window, and switching windows reports `Focus(false)` for the old Pane and `Focus(true)` for the new one, as leaving and returning to the one window do today. A window in the background sends no sizes again, as ADR 0041 requires of a background window, and has nothing to send: its Panes' grids are the size it measured, since the same Client sized them. Sizes still go back and forth only against another Client, which the existing rules cover.

An `Activated` event (ADR 0021), a click on an OS notification or on the "Needs you" list, and a click in the main window on a detached Workspace's Tab or Pane all activate the window that shows the target and show it there, among this Client's windows only: Condr is never brought in front of another application for it, which a notification's click has done already. So does the Diff Tab's Show File, which goes to the Preview Tab. A click that only retargets a viewer Tab does not: a file clicked in Changes, Files or History updates the Workspace's Diff or Preview Tab in whichever window shows it, and focus stays in the sidebar, so the person can go down the list on one screen and read on the other. Keyboard navigation between Workspaces in the main window does not skip detached ones; it lands on their page, so the keys and the sidebar agree on the order. "New Tab" inside a Tab window creates the Tab in its Workspace, which shows it in the Workspace's home window without activating that window. A failed operation is still one `report_error` toast (ADR 0020), now in the window last activated, which is where the person acted; a failure with no window behind it, a connection result, the update check, a configuration save, goes there too, where the person is looking. A question about a file, such as a save that met a changed file (ADR 0045), is asked in the window that shows its Preview Tab.

## Detaching

Every unit detaches from its context menu: a Tab in the Tab strip, a Workspace row and a Device row in the sidebar, as "Open in new window". No keyboard shortcut and no CLI command: a window is this Client's own state (ADR 0021), which the CLI cannot see, and `--focus` reaching the right window is what the CLI needs.

Every unit also detaches by dragging it out of its window, with the drag sources that exist today (`DraggedTab`, `DraggedWorkspace`, `DraggedServer`). GPUI's drag is confined to a window, but on every platform the window that saw the button go down still receives the moves and the release after the pointer leaves it: Windows takes `SetCapture` on the press, AppKit sends `mouseDragged` and `mouseUp` to the view of the `mouseDown`, X11 holds an implicit grab, and Wayland compositors keep pointer focus while a button is held, which the code does not enforce. So a release outside the source window's bounds, read from a `Window::on_mouse_event::<MouseUpEvent>` listener while the GUI remembers what `on_drag_move` last carried, opens the unit's window at the cursor. GPUI exposes the dragged value only during moves, so the GUI keeps its own copy, and clears it on the next press if no release ever came, since GPUI's Windows backend does not handle `WM_CAPTURECHANGED`. Nothing is drawn outside the window while dragging: GPUI paints the drag image inside the window only, and a ghost window waits. A release over another Condr window counts as outside and opens a new window; dropping into that window's Dock would need the drop zones Kit resolves only inside its own window, and is left for later. A maximized window on one screen has no outside; the menu covers that. A Pane dragged out of its window is still a cancelled drag, as today. The gesture is accepted on Windows, verified by hand on macOS, and not promised on Linux, where development is headless.

GPUI's cross-window drag, `external_drag_payload`, was declined for this: it carries file paths only and is implemented for macOS and Wayland, not Windows.

## State

The state file (ADR 0023) keeps the main window as it does and gains the list of detached windows, each with its scope, bounds and display. A scope names its Device by `ServerId` and its Workspace or Tab by the ids the Snapshot persists, never by `ConnectionKey`, which is numbered by load order. A detached window restored before its Server bootstraps shows the Device's connection state until then.

## What this means for the GUI

`Condr` was both the application and its window. It stays the application-level entity, which owns the connections and their `SessionModel`s, the `TerminalPanel`s, pending sizes and geometry, `FilesViewState`, fonts and theme, the update check, Settings and the state file, and keeps a `WindowView` per window, which owns the scope, the focus handle, the content area's size, the sidebars' widths and collapse, Tab-strip scroll and the window's subscriptions. `Condr` is the root view of every window and finds its `WindowView` by the window it draws in, so every render function and listener stays where it is; a window view as an entity of its own would have moved them all. The directory browser and the drop target stay the application's, since only one dialog of the kind and one drag exist at a time. Dock surfaces stay keyed by Tab and are rendered by whichever window shows the Tab; Kit's `DockArea` keeps no window handle, and its subscriptions follow the window that last rendered it, but a surface that changes window is rebuilt through `rebuild_dock`, since an event between the move and the first frame would still reach the old window. `FilesViewState` is the application's because everything in it is keyed by Workspace or Tab: each Workspace's sidebar view and folds, the Diff Tabs' viewers, the Preview Tabs' editors with their unsaved text, and the saves in flight; a Tab that changes window keeps them all. Only its queue of file questions waiting for a window needs one, and is drained by the window the question names.

CONTEXT.md gains two entries when this is accepted: Main window, the one window that is the application, whose closing quits; and Detached window, a window showing one Device, Workspace or Tab moved out of its place, which closing or Bring back returns. "Open in new window" and "Bring back" are the interface's words; float and pop-out are avoided.

## Delivery

In order, each its own change: this ADR; splitting `Condr` with the main window as the one window and no change in behaviour, carried by the existing tests; the menu, the page, the routing and the one-Client rules; the state file; the drag. Tests from the third change on open two windows (`add_window_view`, `VisualTestContext::from_window`, `activate_window` then `run_until_parked`): a detached Tab appearing in the new window and its page in the old, with the right sidebar still there; closing and Bring back each bringing it back; a file clicked in the main window's Changes retargeting a Diff Tab in another window without activating it; a Workspace window's "Needs you" listing only its own Panes; `Activated` activating the right window; the `Focus(false)`/`Focus(true)` order when windows switch; the state file round-tripping its windows. Acceptance on Windows with two screens: one window on each, Codex animating in both, at a usable frame rate and with no size going back and forth.

Left for later, each with its trigger: a Pane detached into a window, which would move it into a new Tab on the Server first, when people ask for one Pane on the other screen; a Tab window that holds several Tabs, when dropping into another window exists; dropping into another window's Dock; a ghost window while dragging outside; a Window menu on macOS, which GPUI does not provide (`SystemMenuType` has only Services).
