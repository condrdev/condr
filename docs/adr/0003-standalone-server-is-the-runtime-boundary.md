# Standalone Server Is the Runtime Boundary

Condr always runs Sessions, PTYs, VT state, agents, and Git/worktree operations in a standalone `condr-server`; the GUI is a client of one or more servers. Local mode only discovers or starts that same server on the GUI machine and then uses the same versioned, length-prefixed `bincode + serde` protocol as a remote connection. The protocol is transport-independent: one Server per machine answers local clients on a private Unix domain socket or Windows named pipe and, when configured, remote clients on a TCP address, often forwarded through an external SSH TCP tunnel (ADR 0013); every TCP connection authenticates and encrypts as ADR 0011 describes. Closing the GUI disconnects without stopping work; reopening it live-attaches through a complete authoritative bootstrap containing stable Server identity and runtime epoch, followed by ordered reliable events and a coalesced terminal visual stream, preserving the Session/layout, current Pane views, and running Agents. The identity/epoch pair distinguishes a live reconnect from a replacement Server after restart. The server owns one active input/resize controller per Server/Session; collaborative control is deferred. This adds process and transport work before the terminal slice, but avoids a second local runtime whose ownership and behavior would diverge. TCP listeners authenticate every peer and encrypt the connection themselves (ADR 0011); capability-based authorization remains deferred.
