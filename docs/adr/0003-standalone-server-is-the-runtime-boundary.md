# Standalone Server Is the Runtime Boundary

Murmur always runs Sessions, PTYs, VT state, agents, and Git/worktree operations in a standalone `murmur-server`; the GUI is a client of one or more servers. Local mode only discovers or starts that same server on the GUI machine and then uses the same versioned, length-prefixed `bincode + serde` protocol as a remote connection. The protocol is transport-independent: local clients use a private Unix domain socket or Windows named pipe, while remote MVP clients connect to an explicitly trusted TCP endpoint, normally a Server loopback listener forwarded through an external SSH TCP tunnel. Closing the GUI disconnects without stopping work; reopening it live-attaches through a complete authoritative bootstrap containing stable Server identity and runtime epoch, followed by ordered reliable events and a coalesced terminal visual stream, preserving the Session/layout, current Pane views, and running Agents. The identity/epoch pair distinguishes a live reconnect from a replacement Server after restart. The server owns one active input/resize controller per Server/Session; collaborative control is deferred. This adds process and transport work before the terminal slice, but avoids a second local runtime whose ownership and behavior would diverge; public network listeners and application authentication, authorization, and encryption remain deferred. Transport protection depends on the external tunnel.
