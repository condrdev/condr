# Tab Kinds Grow Without Breaking Older Clients

Status: accepted 2026-11-27. Amends ADR 0028's rule for an unknown value nested in a known message, for a Tab's content only; replaces ADR 0017's `ShowDiff` and ADR 0018's `ShowFile` with one command.

ADR 0017 gave a Tab a content kind and ADR 0018 the second; Git Graph (ADR 0079) is the third, and a Ports Tab may follow. ADR 0028 gave a new kind no rule of its own: an unknown member of `TabSnapshot.content` makes the whole Session Snapshot unknown, so an older Client that receives one asks for a Bootstrap, receives the same Snapshot, and within ten seconds disconnects with "this Device sends messages this build cannot read; update it", without reconnecting. A Server must therefore never send a new kind to an older Client, and each new kind would bring its own answer: a gate per peer protocol, a field older builds skip, or a raised minimum. That cost would be paid again for every kind. Adding a `oneof` member is the extension ADR 0028 designed; what has to change, once, is what an older build does with a member it does not know.

## Decision

**A Tab whose content this build does not know decodes as an Unsupported Tab**, keeping its id and name, instead of making its Workspace and the Session unknown. The GUI shows it in the Tab strip under its name, and its body says the Tab needs a newer Condr, naming this build and the Server's (ADR 0027). It closes, moves, opens in a window of its own (ADR 0043) and counts for `go-to-tab-N` like any Tab, since all of that goes by id; nothing else applies to it. The Companion lists only Panes, so it shows nothing for it and changes nothing. A Server restoring a Snapshot that holds one, which only a downgrade produces, drops that Tab, logs it and restores the rest rather than setting the whole file aside (ADR 0028); prost keeps no unknown fields, so the Tab could not be written back.

**One command opens every viewer.** `LayoutCommand::ShowViewer { workspace_id, viewer }` creates the Workspace's Tab of that kind the first time and retargets it afterwards, as `ShowDiff` and `ShowFile` did; `viewer` holds the same members as `TabSnapshot.content` less `terminals`, and the reply is `ViewerShown { tab_id }`, shown by the Client that asked (ADR 0021). `ShowDiff` and `ShowFile` leave the domain. On the wire, until 0.2.6 no longer updates in place, a Diff or Preview Tab's `ShowViewer` still goes as `show_diff` or `show_file`, so a newer GUI opens them on a 0.2.6 Server as before, and an older GUI's two decode as `ShowViewer`; only a newer kind goes as `show_viewer`. The reply goes as the member a 0.2.6 GUI reads as `diff_shown`, which it handles as it handles `file_shown`; a 0.2.6 Server's `file_shown` decodes as `ViewerShown`. All of it is marked `compat(0.2.6)`. A Server older than this answers a `show_viewer` with its generic "does not support that request; update it" error (ADR 0028), which the GUI shows with `report_error`; no entry point is gated on the Server's version.

So a new kind of Tab costs one `oneof` member in `TabSnapshot.content`, one variant of `TabContent`, and its own view and requests.

**The first new kind rides beside the list, once.** Builds up to 0.2.6 predate the Unsupported Tab and would still disconnect on a Git Graph Tab. Until 0.2.6 no longer updates in place, the encoder writes a Git Graph Tab into `WorkspaceSnapshot.git_graph`, with its index in the strip, rather than into `tabs`: an older build skips the field and sees the Workspace without that Tab. This build reads a Git Graph Tab from either place, so deleting the field later breaks nothing. Marked `compat(0.2.6)`. The field is boxed, as the Worktree association beside it is: a frame of empty Workspaces decodes to one struct each, and an inline Tab would size them past ADR 0028's decode bound. An older build that moves a Tab by index may land it one place off around the Tab it cannot see; that is accepted.

## Considered

- **A gate per peer protocol**, as ADR 0028 sketched with `SessionEvent::Omitted`. Declined: it is paid per kind, and every message carrying the Session would be framed once per peer protocol.
- **Raising `MIN_CLIENT_PROTOCOL`.** Declined: it refuses every older GUI, and a Companion waiting in store review, for one optional Tab.
- **Viewer kinds as strings with a parameter map.** Declined: the parameters lose their types, the Server still interprets each kind (the Preview Tab follows renames, ADR 0045), and all it saves is one line of `.proto`.
- **Tabs that live only in the Client.** Declined, as ADR 0017 declined a GUI-only viewer: the Tab strip is a projection of the Session, and windows, shortcuts and moves all go by Session Tab id.
- **A second list for every later kind**, which older builds skip for good. Declined: two lists forever for a problem that ends with 0.2.6.

## Tests

`condr-core`: an unknown `TabSnapshot.content` decoding as an Unsupported Tab inside a Snapshot that otherwise decodes; restoring a Snapshot with one dropping that Tab only; `ShowViewer` creating, then retargeting, the Diff, Preview and Git Graph Tabs; a Diff and a Preview Tab's `ShowViewer` going as `show_diff` and `show_file` and Git Graph's as `show_viewer`, each decoding back, and `file_shown` reading as `ViewerShown`; a Git Graph Tab written to `git_graph` at its index and read back into place, and read from `tabs` as well; a decoder without the field, standing for 0.2.6, reading the Workspace without it. The decode-memory bound with the new field.
