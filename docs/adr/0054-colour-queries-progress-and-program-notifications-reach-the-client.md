# Colour Queries, Progress and Program Notifications Reach the Client

Status: accepted 2026-10-29. Builds on ADR 0051, whose libghostty-vt reports each of these; takes three items off its "left for later".

Programs ask their terminal things and tell it things that are not text on the grid. libghostty-vt parses all of it, but until now the Server answered colour queries with Condr's built-in dark palette whatever the person had chosen, and dropped OSC 9;4 progress and every OSC 9 or 777 notification that was not Condr's own Agent event. A program that picks its theme from the background (Codex does, through OSC 11) drew dark-theme colours on a light terminal.

**Colours.** A desktop Client sends `ClientMessage::TerminalColors`: the foreground, background, cursor and 16 ANSI colours it draws terminals with. It sends them when its connection bootstraps and again whenever the person picks another terminal colour scheme. The message belongs to the connection, like `WatchTerminals`, and has no reply. The Server keeps the last colours any Client sent and sets them as every Pane's default colours, and each new Pane's as it is installed. libghostty-vt then answers OSC 4, 10, 11 and 12 with them, and what a program set for itself still wins. The Server also answers `CSI ? 996 n` dark or light by the background's luma, and a program that turned on mode 2031 is told when new colours turn dark into light or back. The last sender wins because a Pane has one set of default colours. Two desktops with different schemes on one Server answer with whichever spoke last. The Companion sends none: its palette is not one the person chose. A Pane's cells still go out as palette indices, so each Client draws them in its own colours.

**Progress.** OSC 9;4 sets a Pane's progress: a percentage, an error, a pause or an indeterminate state, and removing it clears it. So does a percentage in the program's root OSC 7501 record (ADR 0044): `working` shows as progress and `blocked` as a pause. A root report without one, or any other state, ends a progress a report gave but leaves an OSC 9;4 progress alone, and so does the next prompt. A working report without a percentage shows nothing: every Agent turn would otherwise sweep a bar. The Server keeps the latest per Pane. `PaneTerminalSnapshot` carries it in the Bootstrap, and `SessionEvent::TerminalProgressChanged` follows each change, sent only when it differs from the last. As in Ghostty, a progress the program stops updating is dropped after 15 seconds, so a program that died mid-task does not leave its bar behind; the Server notices this at its next idle check of the Pane, within a second. A reset (RIS) and the Terminal ending clear it too. The GUI draws a thin bar along the top edge of the Pane: accent for progress, red for an error, amber for a pause, and a sweeping segment when indeterminate. The Companion keeps the field and draws nothing yet.

**Program notifications.** OSC 9 and OSC 777 `notify` from a program become `SessionEvent::TerminalNotification { pane_id, title, body }`. Condr's own Agent events, which travel as OSC 777 too, are not among them. The Server drops a program's notification in a Pane whose Agent reports its state. There Condr already notifies on Done, Blocked and Error (ADR 0024), and Codex and Claude Code send their own "turn complete" through OSC 9 when they think the terminal shows them. A Pane without such an Agent notifies. The GUI posts it as an OS notification under the existing notifications switch, only when the person is not looking at that Pane, with the program's title, or the Pane's title when it gave none. It is tagged with the Pane like an Agent notification, so a newer one replaces an older one and clicking it opens the Pane. Notifications are not kept: a Client that connects later never sees one, and the Companion gets no push for them.

`PROTOCOL_VERSION` stays `1`, as for ADR 0051, which already pairs a 0.2 desktop with a 0.2 Server. A Server from before answers `TerminalColors` with an error, and a Client from before reads the two new events as unknown and asks for a new Bootstrap.

Tests: colour queries answered with the colours set, a program's own colour outliving a change of defaults, the 2031 report on a flip and none without one, and `TerminalColors` round-tripping and refusing fewer than 16 ANSI colours; a shell asking OSC 11 and `CSI ? 996 n` after a Client's light colours; the GUI's default palette reporting Condr's defaults; progress kept, changed, cleared by remove, reset, exit and the 15-second timeout; a notification reaching the GUI from a plain Pane and dropped in a Pane whose Agent reports.
