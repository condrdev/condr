# The Preview Tab Renders Markdown and Images

Status: accepted 2026-10-08. Reverses two sentences of ADR 0018: "Images and other binaries show a placeholder" and rendered Markdown among the declined items.

Agents write Markdown (plans, READMEs, ADRs) and produce images (screenshots from browser tools, generated diagrams) as often as they write code, and the Preview Tab showed both as their raw bytes or a placeholder. It now renders Markdown, SVG and the common raster formats. Anything GPUI Kit does not already render stays out: HTML, `.mdx` (its JSX would show as stray text), CSV, Mermaid, math, PDF, audio and video.

Images come from the Server like every file, so a remote Workspace shows the same. `FileContent` gains `Image { bytes }` (`bytes image = 4`): the Server sends the undecoded bytes of a file whose extension is `png`, `jpg`, `jpeg`, `gif`, `webp`, `bmp`, `ico`, `tif` or `tiff`, case aside, and the Client decodes them; decoding on the Client keeps a remote Server's CPU out of it and the protocol free of pixel formats. Other binaries keep the placeholder, and the extension decides rather than the content, so clicking an executable never ships its bytes. SVG is text, travels as `Text` under the 1 MiB text limit, and the Client renders it from that text. An image's limit is its own, `MAX_IMAGE_BYTES`: the 2 MiB frame less 64 KiB for the reply's other fields, so the reply needs no frame allowance of its own. A larger allowance, as `PasteImage` has, was declined: the Client's writer carries the terminal stream too, and one 16 MiB reply on a slow link would stall it. Agent screenshots are mostly under a megabyte; a larger file says it is too large, and chunking the reply is the upgrade if that bites.

A Markdown or SVG file opens rendered, and the Tab's header offers Preview and Source, Source being the Editor as before with its search. The choice is the Tab's on this Client only (ADR 0021), not remembered, and every file the Tab shows opens rendered again, except that the Diff Tab's "Show File" opens Source, since only the text has the line it lands on. An image file shows centred and scaled down to fit, never up, with its pixel size and file size in the header. SVG is not scaled up either: GPUI rasterises it at its own size, and a sharp larger copy needs rasterising at the target size, which Kit does not do. There is no zoom, and transparent pixels show the GUI's background, not a checkerboard.

Markdown renders through GPUI Kit's `TextView` from `gpui_kit::base`, which takes the three seams Condr needs where the component wrapper does not. Text runs at most 48 rems wide, centred by padding so the scrollbar stays at the Tab's edge, in the GUI's own colours; code blocks take the terminal's font family, the code font size and the Highlight theme's background and foreground, and are coloured by syntect (ADR 0032) per their info string, through one highlighter per theme because Kit keeps a block's colours only while it gets the same one. Frontmatter shows as Kit's key and value list. Selection and copy work; search is Source's.

An image in Markdown is resolved in the Workspace: relative to the file's directory, or to the root when it starts with `/` as on GitHub, percent escapes decoded, and nothing outside the root. Anything with a scheme, a README's `https://` badges and `data:` URLs alike, shows its alt text and is never fetched: reading a file in Condr does not reach the internet. Kit asks for an image while laying out the blocks on screen; the first time, Condr requests the file with `ReadFile` and decodes it, so a long document fetches only what is scrolled to. A working-tree batch (ADR 0018) drops the cached bytes and marks each image to be asked for again the next time it is drawn, while what it shows stays on screen; bytes that come back the same are not decoded again. Showing another file lets the previous file's images go and frees their atlas space. A link opens `http`, `https` and `mailto` in the system browser, opens a Workspace file in the same Preview Tab, ignores a line fragment such as `#L10`, does nothing for a directory the Files view has listed or a link ending in `/`, and ignores every other scheme. Anchors within the file do nothing, and there is no back button.

Animated GIFs and WebPs always play. GPUI's `img` holds the first frame when the system asks for reduced motion and only advances while the window is focused; an image someone opened to watch is the content, not decoration, as browsers treat it. So the Client splits the frames into one `RenderImage` each and picks the frame from the time, scheduling one redraw for when the next frame is due. That redraws at the animation's own pace instead of every display frame, which matters while terminals stream beside it. A frame delay under 20 ms plays as 100 ms, as browsers do, and an animation keeps at most 256 MiB of decoded frames, dropping the rest.

Tests: the Server sends images by extension under their own limit and SVG as text; the largest image reply fits one frame; Markdown references resolve inside the Workspace only and links reach the browser, a file or nothing; an animation loops through its frames by their delays, plays under reduced motion and schedules one redraw at a time; a short GIF delay slows down; code blocks are coloured by their info string; and in the GUI, an image file and an SVG render with their sizes, Source and Preview switch, Markdown fetches its image from the Server but not a web badge, keeps the decode through a working-tree refresh, and the next file lets the images go.
