# Remote Clipboard Images Are Staged on the Server

Status: accepted 2026-09-05. The implementation is deferred and tracked in [GitHub #29](https://github.com/condrdev/condr/issues/29).

An Agent running in a Terminal on a remote Server cannot read the native clipboard of the machine running the GUI. Forwarding `Alt+V` as terminal input therefore asks the remote Agent to read the remote host's clipboard, while the same shortcut works against a local Server. Condr will bridge that explicit image-paste gesture without adding an Agent-specific conversation or attachment API.

For a Local endpoint, `Alt+V` remains ordinary terminal input and the Agent keeps using its native clipboard integration. For a remote endpoint, the GUI first inspects its local clipboard when the focused Pane receives `Alt+V`. If the clipboard contains no supported image, the GUI forwards the original key unchanged. If it contains a PNG, JPEG, GIF, WebP or BMP image within the 16 MiB payload limit, the GUI consumes the key and sends the encoded image together with the authoritative Server, Session and Pane identities. The selected Pane is captured when the gesture occurs; later focus changes must not retarget the paste. Normal text paste remains unchanged.

The Server accepts the larger inbound frame allowance only for this bounded image input. It validates the message kind, image payload limit, Server and Session identities, and a live target Terminal before creating a file. Other Client and Server messages retain their normal frame limit. The authenticated and encrypted TCP transport already splits a large framed message into bounded Noise records, so clipboard images need no transport-specific representation.

The Server writes each accepted image to a unique file in a private per-user staging directory. On Unix the directory is owner-only and files are created owner-readable and owner-writable; on Windows the staging directory is process-scoped. The wire image format maps to a fixed extension, filenames are generated rather than supplied by the Client, and exclusive creation prevents replacement races. The Server validates the target again after staging, then sends the resulting absolute Server-side path through `TerminalCommand::Paste`, preserving the Terminal's bracketed-paste mode. If staging or routing fails, the new file is removed immediately and the Client receives an error.

Staged paths belong to the Client connection that uploaded them. They are removed when that Client disconnects and when the Server stops; a 24-hour stale-file sweep handles crashes. Images, paths and upload messages are transient input: they are not Session state, are never included in a Snapshot or Bootstrap, do not enter reliable event history, and are not broadcast to other Clients. An Agent must consume the pasted path while its uploading Client remains connected, matching Herdr's lifecycle.

This does not enable OSC 52 clipboard loading. A Terminal program still cannot request clipboard contents. Only the GUI can initiate an image read, in direct response to the person's `Alt+V` gesture, and the Server has no message that asks a Client to read its clipboard. The input follows the same authority rule as `TerminalCommand::Text`, `Paste` and `Key`: it does not require Session control, but it is accepted only from an attached, authenticated Client and targets one Pane.

Consequences: remote image paste continues to depend on the Agent CLI accepting a pasted image-file path, but Condr remains Agent-agnostic and keeps the native CLI as the conversation owner. A large upload can temporarily occupy the connection's ordered Client-to-Server writer, bounded by the image limit. Configurable image-paste shortcuts, local-file drag and drop, image previews, general file transfer, clipboard synchronization and Server-initiated clipboard reads are outside this decision.

The behavioral reference is Herdr commit `9a2a7af5402f2bc67ab24c8b4c14c6dd20a43bb2`, specifically its remote clipboard-image bridge, stable terminal targeting, Server staging and cleanup behavior. Condr uses GPUI's native clipboard image entries instead of Herdr's platform-specific clipboard readers.
