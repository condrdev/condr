# Herdr v0.8.2 SSH remote implementation

Scope: Herdr commit [`9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c`](https://github.com/herdrdev/herdr/tree/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c). Condr comparison uses local checkout HEAD `165a4504c45e0ef71196b5a9d6cc871a650e6d0c`.

## Conclusion

Herdr does not expose a third server listener and does not use SSH TCP forwarding. Its SSH mode is a client-side adapter: a private local IPC proxy launches system `ssh -T`, the remote command connects to the remote Herdr Unix socket, and both sides copy the existing binary protocol byte-for-byte over SSH stdio. There is no `-L`, `-R`, or `-W` in the bridge command. ([local bridge command](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1816-L1868), [remote bridge](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/host_unix.rs#L8-L48))

```text
local Herdr client
  <-> private local socket / named pipe
  <-> local bridge
  <-> ssh -T TARGET 'exec REMOTE_HERDR remote-client-bridge'
  <-> remote bridge
  <-> remote Herdr Unix socket
  <-> long-lived remote Herdr server
```

This shape is reusable for Condr, but SSH is a third **connection mode**, not a third bindable server endpoint.

## Entry and configuration

- `herdr --remote <target>` is accepted only for the default app launch. The parser rejects duplicate/empty targets and targets beginning with `-`; it also supports a named session, local/server keybinding choice, and opt-in live handoff. ([argument parser](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L38-L160), [main dispatch](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/main.rs#L536-L576))
- `remote.manage_ssh_config` defaults to `true`. Disabling it means Herdr invokes plain system `ssh` with the user's configuration unchanged. ([config model](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/config/model.rs#L963-L977), [default config text](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/main.rs#L426-L435))
- With management enabled, Herdr creates a temporary config which includes the user and system SSH configs first, then supplies fallback `ServerAliveInterval 15` and `ServerAliveCountMax 4`. On Unix it also uses a private per-attach control socket with `ControlMaster=auto` and `ControlPersist=yes`; Windows disables multiplexing. ([generated config](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1773-L1813), [command options](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L606-L620), [platform policy](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/platform/unix_common.rs#L22-L30))

## Binary and server bootstrap

- Before attaching, Herdr runs SSH commands to detect `uname -s`/`uname -m`, searches known locations and the login-shell `PATH`, then accepts a remote binary only when both its version string and client protocol match the local build. ([platform detection](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L202-L245), [discovery and match](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L711-L728), [version/protocol check](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L813-L884))
- If no matching binary exists, an interactive user must approve installation. Herdr selects the current local executable when platform-compatible, otherwise downloads the matching release asset, then streams it through SSH to a temporary path and commits it as `~/.local/bin/herdr` with `chmod 755` plus `mv`. Downloaded assets are SHA-256 checked when a checksum is present, and stable release selection rejects a missing checksum. ([install decision](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L645-L709), [source selection](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L926-L980), [streamed install](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L489-L579), [download verification](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1430-L1456), [stable checksum requirement](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1524-L1555))
- The launcher probes `REMOTE_HERDR status server --json`. Protocol/version mismatch, an older non-detached daemon, or a replaced binary may require an approved restart; `--handoff` uses live handoff only when the running server advertises support. Noninteractive protocol mismatch fails instead of stopping the server silently. ([status and restart classification](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1009-L1075), [status schema](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1213-L1273), [confirmation policy](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1275-L1367))
- The hidden remote command is `exec REMOTE_HERDR [--session NAME] remote-client-bridge`. That helper accepts a compatible existing server, otherwise starts a detached daemon and waits up to five seconds for its client socket before connecting. ([command construction](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1617-L1625), [remote server ensure](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/host_unix.rs#L51-L69), [daemon detachment](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/server/autodetect.rs#L179-L235))

## Bridge and protocol

- The local adapter creates a per-process/per-target/per-session private IPC endpoint. On Unix it restricts the socket to `0600`; the hidden local client is then launched against that endpoint using `HERDR_CLIENT_SOCKET_PATH`. ([listener setup and cleanup](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1661-L1757), [client launch and path](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L2114-L2154))
- Each accepted local connection starts `ssh -T TARGET REMOTE_COMMAND`, pipes the local stream to child stdin and child stdout back to the stream, inherits SSH stderr, and treats a nonzero SSH exit as connection abort. The remote helper performs the same two-way copy between stdin/stdout and the remote Unix socket. ([local byte pump](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1816-L1868), [remote byte pump](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/host_unix.rs#L8-L48))
- The bridge is protocol-blind. It carries the normal version-20 Herdr protocol: bincode payloads prefixed by a four-byte little-endian length, bounded to 2 MiB normally or 32 MiB for graphics, with exact-version rejection. ([wire constants](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/protocol/wire.rs#L15-L31), [framing implementation](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/protocol/wire.rs#L900-L967), [version check](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/protocol/wire.rs#L995-L1021))

## Lifecycle and reconnect

- The local bridge exists only while the spawned local client runs. Dropping it signals the accept loop, removes the owned local endpoint, and joins the bridge thread; the SSH child is tied to the bridged connection. ([remote launch scope](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L162-L199), [bridge drop](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1747-L1757), [child wait](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1849-L1868))
- The remote server is a separately detached daemon, so loss of SSH removes the client connection rather than intentionally stopping server-owned panes. Herdr's client does not automatically reconnect: EOF returns `ConnectionLost` and the error tells the user to rerun the generated remote command. ([daemon lifetime](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/server/autodetect.rs#L179-L235), [disconnect behavior](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/client/mod.rs#L297-L305), [client loop exit](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/client/mod.rs#L1886-L1906))

## Security and platform boundaries

- Herdr delegates SSH authentication, host verification, aliases, jump hosts, and credential prompting to the installed OpenSSH client and its included configs. The command builder adds no host-key-relaxation flag; auth failures merely suggest verifying direct `ssh` access and loading passphrases into `ssh-agent`. This is an inference from the constructed command and error path, not a separate Herdr security layer. ([SSH command builder](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L451-L487), [managed options](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L606-L620), [auth hint](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote.rs#L16-L24))
- The binary `Hello` carries protocol/render/terminal fields but no application credential. Access control therefore comes from SSH plus the remote OS user's private local socket, not from SSH-specific authentication inside Herdr's protocol. ([Hello schema](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/protocol/wire.rs#L341-L362), [remote socket connection](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/host_unix.rs#L8-L20), [server socket permissions](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/server/socket_paths.rs#L60-L74))
- Supported remote hosts are Linux or macOS on `x86_64`/`aarch64`. A local Windows client has a dedicated bridge implementation, but `remote-client-bridge` explicitly rejects Windows remote hosts and Windows disables SSH control-socket multiplexing. ([platform matrix](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L202-L245), [Windows local bridge](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L1871-L2018), [Windows remote rejection](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote.rs#L1-L14))

## Factual comparison with Condr

- Condr currently models `Endpoint::{Local, Tcp}`; the same enum owns both `bind()` and `connect()`, and `ClientConnection::connect` immediately performs the shared `Hello`/`Welcome`/`Bootstrap` flow over the resulting `EndpointStream`. ([Condr endpoint](https://github.com/condrdev/condr/blob/165a4504c45e0ef71196b5a9d6cc871a650e6d0c/crates/condr-server/src/endpoint.rs#L16-L68), [Condr client connection](https://github.com/condrdev/condr/blob/165a4504c45e0ef71196b5a9d6cc871a650e6d0c/crates/condr-server/src/server.rs#L121-L189))
- Condr's GUI Add Server flow currently parses only `SocketAddr` and creates `Endpoint::Tcp`; SSH tunnel setup is therefore external today. ([GUI flow](https://github.com/condrdev/condr/blob/165a4504c45e0ef71196b5a9d6cc871a650e6d0c/crates/condr-gui/src/app/dialogs.rs#L136-L160))
- Herdr's reusable boundary is therefore a client-only `SSH target -> stream` adapter. Treating it as product mode `Local | TCP | SSH` is accurate; adding `Endpoint::Ssh` to Condr's currently bindable server endpoint enum would not match Herdr's architecture because no server binds an SSH endpoint. ([Herdr orchestration](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/attach.rs#L162-L199), [remote bridge destination](https://github.com/herdrdev/herdr/blob/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c/src/remote/host_unix.rs#L8-L20))

## Minimal borrowing recommendation

Borrow the transport shape, not the full remote installer:

1. Keep server bind endpoints as `Local | Tcp`.
2. Add a client connection target `Direct(Endpoint) | Ssh { target, remote_socket }`.
3. For SSH, run system `ssh -T target 'condr-server remote-client-bridge ...'`; the remote helper ensures/connects the private local Condr endpoint and copies the existing framed protocol over stdio.
4. Keep host-key checking and authentication in OpenSSH, capture SSH stderr for GUI errors, and reconnect by starting a fresh SSH bridge followed by Condr's existing authoritative bootstrap.

Herdr's binary discovery, self-install/update, live handoff, managed SSH config, and control-socket reuse are independent conveniences. They are not required to establish Condr's third connection mode and should be added only when product requirements demand them.
