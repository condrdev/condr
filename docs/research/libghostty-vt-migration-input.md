# libghostty-vt 迁移评估：输入与控制通道

调查日期：2026-10-28，基于 Condr 提交 `afcd14a`。对照的是 ghostty-org/ghostty main 提交 `46e9dc9a927b2e7e7cba79e6902c176127dbdf2c`（2026-10-28）中 libghostty-vt 的 C 头文件；行为细节按同一提交的 Zig 源码核对过，引用时标「源码」。Rust 绑定 `libghostty-vt` 0.2.2 比 main 旧，缺的部分记在「风险与未决」。这次只读代码，没有改代码，也没有实际运行 libghostty-vt。

引用约定：Condr 路径省略 `crates/condr-core/src/terminal/` 前缀，其他 crate 写全路径；libghostty-vt 头文件省略 `include/ghostty/vt/` 前缀；源码路径从 ghostty 仓库根目录写起。

结论：输入与控制通道的非测试代码约 2480 行，libghostty-vt 能接管约 890 行。能整块删掉的是 `OscScanner`（339 行）：OSC 7、9;9、1337、777、7501、133 和 RIS，libghostty-vt 都能自己解析，`OSC 7501 ; ?` 的回复也按字节流顺序写出，所以不必再赶在 VT 之前截获。按键编码（kitty 和 legacy）、鼠标编码，以及颜色和尺寸查询的应答也可以交给 libghostty-vt。PTY 写队列、鼠标路由与按下/松开配对、cwd 和 agent 探测、ConPTY 光标稳定是 Condr 自己的策略，libghostty-vt 不涉及。迁移成本主要在按键上：libghostty-vt 要物理键、unshifted codepoint 和 consumed mods，Condr 协议的 `TerminalKey` 只有文本和命名键，Server 只能近似合成。另外有几处 legacy 编码和 Condr 现在的行为不同，比如 Shift+Enter。libghostty-vt 能带来 13 项新功能，其中 modifyOtherKeys、mode 2048 尺寸报告和终端查询应答只需改 Server，其余都要改协议。

## 风险与未决

1. **DA1 和尺寸查询必须由回调回答。** `DEVICE_ATTRIBUTES` 回调为空时，libghostty-vt 不回 DA1（`terminal.h:2262-2270`，源码 `stream_terminal.zig:1703-1705`）；alacritty 现在固定回 `?6c`（`alacritty_terminal-0.26.0/src/term/mod.rs:1257-1262`）。Claude Code 和 Pi 把 DA1 回复当作 7501 探测的结束标志（ADR 0044），漏装这个回调，它们就会一直等到超时。CSI 14/18 t 也一样，依赖 `SIZE` 回调。
2. **libghostty-vt 默认会以 Ghostty 的身份回答查询。** 不装 XTVERSION 回调时回复 "libghostty"（`terminal.h:2228-2233`）；XTGETTCAP 按 Ghostty 自己的 terminfo 表回答（源码 `stream_terminal.zig` 的 xtgettcap 分支），而 Condr 设置的是 `TERM=xterm-256color`（`runtime.rs:95`）。agent CLI 会不会因此把 Pane 当成 Ghostty 而开启某些特性，未确认。至少要设置 XTVERSION 和 `TERMINFO_NAME`。
3. **按键行为会变。** 涉及 Shift+Enter 发 LF、Ctrl+Enter/Tab、Shift+Esc、Ctrl+数字，以及 Cmd 是否输出文本（取决于 Server 的编译平台），见接管清单的 kitty 和 legacy 两行。迁移前要用 Codex、Claude Code、OpenCode 在 legacy 和 kitty 两种模式下各测一遍。在 Windows 上，kitty 探测总是被 conhost 抢先（ADR 0035），所以那里走的基本都是 legacy 路径。
4. **协议给不出 libghostty-vt 需要的按键输入。** 缺的是物理键、consumed mods、锁定键和 unshifted codepoint，Server 只能按 US 布局去猜。按键有三个来源（GUI、Companion、CLI），其中只有 GUI 拿得到 GPUI 的 `key` 和 `key_char`；GPUI 是否暴露扫描码，未确认。如果给协议加字段，按 ADR 0028 只能加可选字段，旧客户端没有这些字段时退回到猜测。
5. **OSC 777 的缓冲只有 2048 字节**（源码 `src/terminal/osc.zig:361`、`osc.zig:1060-1065`），比 Condr 现在的 4 KiB 小。超长的事件会被 libghostty-vt 当作无效序列丢掉，也不会交给 unknown 回调，因为 unknown 回调只接收 libghostty-vt 没实现的 OSC 编号（`terminal.h:899-905`）。正常情况下 agent 事件远小于 2 KiB（detail 不超过 200 字符，session_id 和 prompt_id 各不超过 256 字节，见 `crates/condr-core/src/agent/event.rs:140`、`event.rs:145`），但极端转义下会不会超过，未确认。两个办法：给 hook 补一个长度上限测试，或者改用 `vt_write_until` 在 OSC 边界自己读取（`terminal.h:3346-3472`）。
6. **7501 的处理细节和 ADR 0044 不完全一致。** 重复 state 时怎么取、回复文本、终止符跟随请求，见 `OscScanner` 一行的差异 (b)(e)。要把 Condr 现有的 7501 测试（`crates/condr-core/src/agent/program_status.rs:217` 起，以及 OSC 扫描器的测试）在 libghostty-vt 上重跑一遍，再决定接不接受这些差异；Claude Code 和 Pi 能否接受带列表的长回复，未实测。
7. **标题栈功能会丢失。** libghostty-vt 不实现 CSI 22/23 t（源码 `stream_terminal.zig:810-812`），vim 这类程序退出后不会恢复原标题。侧栏的标题来自 OSC 0/2，影响不大，但相比现在是退步。
8. **回调同步执行，且不能重入**（`terminal.h:79-84`）。`print_notice` 不能在回调里写；剪贴板读取这类同步回调也没办法等远端客户端回应。
9. **Rust 绑定 0.2.2 只有 10 个 effect**：pty_write、bell、enquiry、xtversion、title_changed、pwd_changed、size、color_scheme、device_attributes、clipboard_write（`libghostty-vt-0.2.2/src/terminal.rs:1562-1704`）。本块要用的 PROGRAM_STATUS、SEMANTIC_PROMPT、RESET、DESKTOP_NOTIFICATION、PROGRESS_REPORT、UNKNOWN_SEQUENCE、CLIPBOARD_READ、`ghostty_terminal_paste` 和 `vt_write_until` 都没有。按键事件的 consumed_mods、utf8、composing 已经有（`key.rs:298-338`），粘贴只有 `paste::encode`（`paste.rs:69`）。要么等上游补齐，要么自己写 FFI。
10. **行数都是估算。** 「可删」是按函数整体是否由 libghostty-vt 承担来算的，新写的 150–200 行胶水没有扣除。
