# Herdr v0.8.2 Server/Client Findings

Scope: exact Herdr commit `9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c`, checked from the local checkout at `/tmp/herdr-v082`. Line references below are to that checkout (the commit is immutable and is also available at `https://github.com/herdrdev/herdr/tree/9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c`).

## Executive summary

Herdr's server is a long-lived owner of sessions, PTYs, rendering, and persistence. The normal TUI client is a thin local-socket client; disconnecting it removes a client connection but does not stop the server or runtime. A server with zero clients still polls events and renders a virtual/headless view. The binary client protocol is a strict, versioned, little-endian length-prefixed bincode stream with a Hello/Welcome exchange. `session.snapshot` is a separate newline-delimited JSON API bootstrap, not a message in the binary render stream. Remote mode is an SSH stdio byte bridge to the same remote Unix socket. Restart persistence restores structure and (optionally) pane history/native agent sessions, but not arbitrary live processes.

## Server lifecycle and zero-client behavior

- Auto-detection first probes the configured local socket, rejects a stale/unresponsive endpoint, otherwise launches `herdr server` detached with inherited socket/API overrides cleared, waits for the socket, and then starts the client (`src/server/autodetect.rs:1-9,39-91,179-236,242-306`).
- `HeadlessServer::new` binds the client socket, applies owner-only permissions, initializes an empty client map, and sets configured `headless_size` and `effective_size` (`src/server/headless.rs:464-545`). The run loop continuously accepts clients, drains server/API events, polls clients, runs scheduled work, and renders/streams (`src/server/headless.rs:535-545,545-918`).
- Foreground sizing is explicitly separate from the no-client size: when no foreground client exists, `effective_size` is reset to `headless_size` and the headless view geometry is used (`src/server/headless.rs:1155-1226`). Removing a client only removes its connection; if needed another client is promoted and the shared runtime is resized. There is no “last client closed => stop server” path (`src/server/headless.rs:1555-1650,3304-3314`).
- The renderer handles an empty target list by still rendering the virtual frame and returning to the event loop (`src/server/headless.rs:4426-4490`). Explicit shutdown is a server/API operation (`server.stop` sets the stop flag; `src/api/server.rs:340-380`) and final cleanup removes sockets after saving (`src/server/headless.rs:4857-4905,4958-4967`).

## IPC, handshake, framing, and versioning

- Herdr's local transport is `interprocess` local sockets: Unix filesystem sockets and Windows namespaced named pipes (with a marker file). The listener uses non-reclaiming bind semantics (`src/ipc.rs:1-79`). Client and API socket paths are prepared separately; Unix client sockets are owner-only (`src/server/socket_paths.rs:14-74`, `src/api/server.rs:59-135`).
- The binary wire protocol declares protocol version `20`, normal frame limit 2 MiB, graphics frame limit 32 MiB, and a 4-byte little-endian length prefix (`src/protocol/wire.rs:1-31`). `ClientMessage::Hello` carries version, terminal geometry, render encoding, keybinding mode, and launch mode; subsequent variants include input, resize, detach, attach/control, clipboard, and observe messages (`src/protocol/wire.rs:341-452`). `ServerMessage` includes `Welcome`, `Frame`/`Terminal`, shutdown, notifications, clipboard, title, and input-mode messages (`src/protocol/wire.rs:659-728`).
- Encoding is bincode (standard configuration), followed by a `u32` little-endian payload length and an explicit flush. Reads use `read_exact`, reject a claimed length above the selected limit before allocation, decode exactly one value, and reject trailing bytes (`src/protocol/wire.rs:900-980`). Version compatibility is exact: zero and every version other than the current version are rejected; there is no old/new compatibility window (`src/protocol/wire.rs:982-1021`).
- The server handshake runs on a blocking client thread with a four-second receive timeout. The first frame must be Hello, version and fields are validated/clamped, and Welcome either carries the accepted encoding/version or an error; only then is the connection inserted into the server (`src/server/client_transport.rs:515-690`). The read loop applies the normal/graphics limits and disconnects on malformed or oversized frames (`src/server/client_transport.rs:743-805`). Control messages and render frames have separate writer queues so control traffic remains reliable (`src/server/client_transport.rs:706-740`).

Herdr also exposes a distinct local JSON API. Each request opens a local stream, writes one JSON object plus newline, and reads one JSON response (`src/api/client.rs:14-99,158-174`). This is intentionally separate from the bincode TUI stream.

## `session.snapshot` and reconnect

- The `session.snapshot` API handler constructs a versioned structural snapshot containing protocol metadata, focused workspace/tab/pane IDs, workspaces, tabs, panes, layouts, and agent metadata (`src/app/api/session.rs:1-57`; schema in `src/api/schema/session.rs:8-22`). The socket API documentation calls it a one-time bootstrap for a client-maintained cache, followed by event subscription; clients call it again after reconnect or when the cache is stale (`docs/next/website/src/content/docs/socket-api.mdx:118-125`).
- This snapshot is not sent over the binary client protocol (`src/protocol/wire.rs:341-452` has no SessionSnapshot client message). A normal TUI connection instead receives its first complete render after Hello: each connection starts with a fresh `ClientRenderState` baseline (`src/server/render_stream.rs:12-119`); semantic encoding sends the frame, while the ANSI encoder emits a full redraw when its baseline is empty or the size changes (`src/protocol/render_ansi.rs:55-91`). The client blits `Frame` or writes `Terminal` bytes and commits its local baseline (`src/client/mod.rs:1674-1702`).
- The TUI client does not automatically reconnect: connection loss and `ServerShutdown` terminate the client loop, while a clean exit sends `Detach` (`src/client/mod.rs:1818-1889,1901-1906,1913-1962`). Reopening the client relies on the server's still-live runtime and a new handshake/initial render.

## SSH remote bridge

- `herdr --remote target` ensures a matching remote binary/server, creates a private local forwarding socket, starts an SSH stdio bridge, and launches a local client subprocess against that socket (`src/remote/attach.rs:162-199,2114-2154`). The bridge command is `exec <remote-herdr> ... remote-client-bridge` (`src/remote/attach.rs:1617-1625`).
- The remote bridge process ensures the remote server is running, checks remote protocol/version/capabilities through `herdr status server --json`, connects to the remote client socket, and copies bytes between the socket and SSH stdin/stdout with flushes (`src/remote/host_unix.rs:8-69`). The local side uses a private `0o600` listener; each accepted local stream is bridged to a separate SSH process, with bidirectional copy threads and child-status propagation (`src/remote/attach.rs:1661-1868`).
- Before attaching, remote status mismatch can trigger an explicit live handoff only when opted in; otherwise the code prompts and may stop/restart the remote server. Noninteractive mismatch fails rather than silently replacing a server (`src/remote/attach.rs:1009-1075,1213-1382`). The documented default is restart (fresh processes), while live handoff is experimental (`docs/next/website/src/content/docs/persistence-remote.mdx:38-89`; `docs/next/website/src/content/docs/session-state.mdx:91-108`).

## Client control and resize policy

- App clients are tracked separately from direct terminal attachments. Activity promotes an app client to foreground; disconnecting the foreground promotes the newest remaining client, and with no app clients the server returns to headless sizing (`src/server/headless.rs:1555-1640`).
- A direct terminal attach has one writable owner. A second owner is rejected unless takeover is requested; takeover sends shutdown to the previous owner and removes it. Observers are read-only (`src/server/headless.rs:2797-2900`; user-facing policy in `docs/next/website/src/content/docs/persistence-remote.mdx:103-153`).
- Resize messages from a foreground app client update the shared runtime size; observer/direct-attach resize is scoped to that client/runtime. Client-side resize polling sends a `Resize` message on terminal geometry changes (`src/server/headless.rs:3233-3303`; `src/client/mod.rs:1660-1672,2496-2547`). Input promotes the sender and performs a pre-input resize; detached clients cannot control the runtime (`src/server/headless.rs:2910-2988`).

## Persistence and restart

- Session and optional history are JSON files, written through a temporary sibling (`*.json.tmp`) and atomically renamed; symlink targets and parent creation are handled (`src/persist/io.rs:44-75`). Missing, unreadable, malformed, or newer-version files are ignored on load (`src/persist/io.rs:113-173`).
- Snapshot version 3 stores workspaces, workspace identity/cwd/worktree membership, tabs/layout/focus, pane cwd/labels/agent metadata/session references, and launch argv. History is a separate optional record (`src/persist/snapshot.rs:11-110,251-380`).
- Restore preserves saved structure and starts each ordinary pane with a fresh shell in its saved cwd (or a fallback cwd); saved history may be replayed when enabled. Native resumable agents can be restored through a pending native-resume path. Failed panes/tabs are pruned while successful workspaces survive (`src/persist/restore.rs:64-117,257-303,446-566,575-781`).
- App startup restores persisted state when session mode is enabled; an empty/missing/invalid snapshot starts empty, and only then may startup seed an initial workspace. Periodic and final server saves run in background/final shutdown paths (`src/app/mod.rs:380-479`, `src/app/session.rs:3-108`, `src/server/headless.rs:911-914,4801-4807`).
- The documented restart contract is therefore: layout survives; live processes do not; recent screen survives only as optional history; native agent conversations survive only where native resume is supported (`docs/next/website/src/content/docs/session-state.mdx:8-89`).

## Alignment and recommendations for Murmur

Murmur's current architecture docs align with the important boundaries: a standalone server owns Session/PTY/VT runtime, GUI close only disconnects, local endpoints are private, protocol uses length-prefixed `bincode + serde` with Hello/Welcome, one active controller owns input/resize, and restart persistence is intentionally limited (`CONTEXT.md:7-50`; `docs/adr/0003-standalone-server-is-the-runtime-boundary.md:1-3`; `docs/mvp-plan.md:13-19,52-61`).

The following differences should remain explicit in Murmur's design:

1. **Transport.** Herdr v0.8.2's binary client endpoint is Unix socket/named pipe; SSH carries that byte stream, not a native Herdr TCP listener. Murmur's transport-independent framing and optional trusted loopback/TCP endpoint are reasonable, but test TCP with the same bounded framing and keep loopback/private defaults (`docs/mvp-plan.md:17,29`).
2. **Bootstrap contract.** Herdr's JSON `session.snapshot` is a separate request/response cache bootstrap, while binary reconnect starts with a full render baseline. Murmur's planned authoritative structural bootstrap plus ordered event cursor is stronger and better for a GUI; define it as a distinct protocol phase and do not confuse it with the durable snapshot (`docs/mvp-plan.md:19,29`).
3. **Reconnect.** Herdr's client exits on disconnect and relies on a user-launched new client. Murmur should add GUI retry/reconnect, but preserve server-owned PTYs and require a fresh Hello plus authoritative bootstrap before events (`src/client/mod.rs:1818-1962`; `docs/mvp-plan.md:19,61`).
4. **Controller lifetime.** Adopt Herdr's explicit foreground/owner rules, including release on disconnect, promotion, and takeover; reject concurrent writers rather than letting resize/input races mutate a shared runtime (`docs/mvp-plan.md:19,29,61`).
5. **Restart scope.** Keep the Murmur MVP promise of fresh shells and structure-only persistence; Herdr's optional history/native-agent restore is useful post-MVP but adds format, security, and resume failure policy (`docs/mvp-plan.md:33,61`; Herdr evidence above).
6. **Remote startup safety.** SSH bridge discovery and protocol mismatch handling should be explicit. Do not silently stop a running remote server; require a trusted endpoint/authorization decision and report incompatible versions before attaching. Defer Herdr-style live handoff until the basic bridge/reconnect contract is stable.
7. **Identity.** Herdr's binary handshake has no durable server identity, and its API snapshot is not a server-instance token. Murmur's reconnect/event-cursor design should include a stable Server identity/epoch so a GUI can distinguish reconnecting to the same runtime from connecting to a replacement (`docs/mvp-plan.md:19,61`).
